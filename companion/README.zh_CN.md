# DS 中枢（Pocket Hub）

修改本项目的 Agent 必须先读[根目录指令](../AGENTS.zh_CN.md)和
[App／Runtime／固件强制可靠性准则](../docs/development/cross-stack-reliability.zh_CN.md)。
其中规定回归、3 秒首回复、连接恢复和多端一致性验收。下文的能力说明不能
作为这些要求已经通过验证的证据。

安卓中枢以 DS 为中心：你和她说话，她把事情交给帮手，左侧边栏列出所有任务和帮手。它位于手机上的各个 AI 助手和 Claude Pocket 设备之间，读取
已登记 App 的通知（默认是 Claude 和 Codex），把最近的几条整理成一个小的消息流，
通过低功耗蓝牙发给设备。App 说的是和 Claude 桌面端相同的 Hardware Buddy 线协议，
外加[固件文档](../docs/claude-pocket.zh_CN.md#对话)里说明的中枢扩展。

App 里还有一个和DS说话的聊天框。在那里输入的话通过 HTTP 发给
[Runtime](../runtime/README.zh_CN.md)。你提的每个需求是一件事，在 Runtime 上有
一张卡；App 一直等着 Runtime 说哪些卡变了（`/v1/feed`），把它们显示出来并报告给设备：
DS此刻在干什么、每件事的卡、正在做的事和它们最近的两步。帮手要做需要你确认的操作时，
App 在顶栏下方提供审批提醒和完整操作详情，设备上也显示请求，在哪一边回答都行。App 还会告诉设备当前选中
的 Runtime 上有哪些 agent。

在设备上按住 `确认` 可以录一段语音消息。App 通过蓝牙收下音频，转给 Runtime，由
Runtime 识别成文字并像打字的消息一样回答。这条设备录音路径和手机麦克风分开；手机麦克风默认在手机上转录（见下文何时交给电脑）。按下时设备屏幕上有
一件事（第二屏的那张卡、第三屏选中的那件）时，设备会说明这句话是对它说的，App 原样
带给 Runtime。

中枢是一个独立的参与者，不是 Claude 的功能。它不认识任何具体的助手；一个“来源”
只是一个安卓包名加一个显示名称，可以在 App 里继续添加。

## 侧边栏手机界面

DS 是主线：陪你聊天、接需求、把事情交给帮手。你只需要说和看，所以 App 不提供
选帮手、选档位的控件；想指定就直接说「让 Codex 做，认真点」，由 DS 安排。左上角
☰ 打开侧边栏，里面是 App 的所有位置：

- **和小幽聊天**：持久保存的消息时间线。发送后立即出现用户气泡；小幽的回复像聊天软件那样
  写完一条整条弹出一条。派发任务时保留小幽的回复并附任务入口，完成总结作为新消息出现，不自动切页。
  电脑上开的会话不会出现在这里。可加载更早的消息；任务卡被裁剪或移除时，手机已保存
  的主对话消息仍保留。
- **任务**：按手机时区中的创建日期分为「今天」「昨天」和具体日期，每天新的在前；每项
  带创建时间。置顶任务单独成组并显示完整日期与时间。完成、审批、接着做都不改变原始
  日期或位置。长按任务（或在任务页点 ⋯）可置顶、归档、停止；按来源电脑保存，归档任务
  可从「已归档」找回。标题以 runtime 为准，设备、手机、电脑三端一致。
- **帮手**：每位帮手一行（Codex、Claude，然后是其他），显示状态。帮手页列出 DS 派给
  它的事（每条能回到所属任务）和电脑上开的会话；帮手页底部可以直接给它派活，不经 DS 安排。
- **连接与设置**：设备和电脑的连接、伴侣形象、用量、固件、通知和偏好。

打开 App 先看到小幽本人。她的动作跟着真实状态变：待机时轻轻呼吸，听你说时侧头、
身后光圈外扩，想的时候上下浮、旁边三个点，流式回复出来时轻轻弹动，帮手做完时蹦一下。
点她一下会在手机上回你一句。交出去的事会有一封小信飞到帮手的小标签上，帮手在做时
标签转圈，做完变绿。按住中间的大麦克风说话：App 内置中文流式模型提供临时文字，松开后由 SenseVoice
完成最终识别，再只把最终文字发给 Runtime。不依赖 Android 系统语音识别服务或系统离线语言包。
取消手势或离开页面会丢弃录音和结果；录音只留在内存中，最长 30 秒。录音优先用系统的“语音识别”
通道（没有时退回普通麦克风）。手机没认出来、或者在「偏好与运行记录」里打开「手机说话交给电脑识别」
时，这段录音会发给连着的电脑，用和设备录音相同的识别；其余情况录音不会上传。
需要允许麦克风权限。麦克风会立即开始采集，模型在另一工作线程加载，加载期间说的话也会保留。
开始实际采集后才显示录音提示；识别失败时，麦克风下方会保留具体原因，直到下次按住。
打字时也可以用输入法自带的语音输入；左边的键盘进入对话记录打字。还没添加电脑时，首页会引导你先连电脑。
随身小幽页显示设备屏幕的样子，可以连接或断开设备、进入固件，并给以后固件增加的玩法
留了位置。

任务页先列出这件事的几步（DS 拆分需求 → 帮手处理及最新进展 → DS 告诉你结果），
下面是这件事的对话，在这里发的话立即出现并接着这件事。帮手最终结果原文与小幽总结
分别保存，长原文另存附件；小幽仍在总结时，原文与文件即可查看。总结的流式气泡独立于
正在进行的主对话。新增消息 ID、归属和结果字段兼容旧 Runtime；更新 Python 代码后需
重启 Runtime 才启用新结果功能。此前已被丢弃的消息或原文无法由手机恢复。
电脑上的会话可以在这里接着聊：电脑上那一轮停下以后，在会话页发的话会交给对应的帮手，在原来的
项目目录里接着那个会话跑一轮，回复也会出现在电脑上；这件事另开一个「接着：……」任务。电脑上这一轮
还在跑时不让发，免得两边同时改一个会话。需要 Runtime 0.8.1。
状态只用一个带颜色的词：蓝色进行中，橙色等你确认，结束的任务不写状态。伴侣形象
只改变 DS 在聊天里的样子，不决定事情交给哪位帮手。附件用的加号在 runtime 能接收
手机文件之前先不显示。草稿按电脑和任务分别保存。

DS、Codex、Claude 使用保留源图集裁切的透明 256px 头像。用 JDK 17 运行
`android/tools/PreparePortraits.java` 可重新生成。Claude/cc 共用一个形象，其他帮手
显示带名字的占位形象。电脑消息使用实际观察到的作者头像，DS 转述仍显示 DS。
可选的轻微呼吸动画在头像隐藏或移除后停止。

待确认操作只在有事等待时，在顶栏下方显示一条提醒。详情保留操作原文和来源电脑，
显示提交中、成功或失败重试反馈。只有 waiting 状态不会生成审批按钮；电脑审批需要
实时权限桥，只读提醒不能回答。Runtime 管理的任务可以二次确认后停止。

手机同时监控最多八台已配对 Runtime 的审批；App 在后台且监控服务运行时也继续观察。
安卓审批通知会打开来源请求。即使当前选择了另一台电脑，回答仍路由回该审批的来源
Runtime。任务列表、对话、帮手和固件管理继续使用当前选中的 Runtime。某审批来源断开
后，它的可操作请求会撤下，直到取得新的 feed。接收提醒需要安卓通知权限；读取其他
App 通知的“通知使用权”是另一项权限。

已登记的任务图片直接显示预览。点图片查看已下载原图的全屏画面，再通过安卓选择位置
保存，或交给其他 App 打开。文件卡显示名称、MIME 类型和大小，也提供保存和打开操作。
下载使用来源 Runtime 和已登记附件 ID，核对大小及 SHA-256 后缓存，失败可以重试。
首版不上传手机文件，不导入电脑对话里提到的任意路径或网址；普通附件在手机查看，
不经 BLE 传到设备。

Runtime HTTP 请求和附件字段分别见
[HTTP 接口](../runtime/README.zh_CN.md#http-接口)和
[任务图片和可下载文件](../runtime/README.zh_CN.md#任务图片和可下载文件)。
实现位于 `runtime/xiaoyou_runtime/server.py`、`cards.py` 和 `artifacts.py`；代理回复的
schema 是 `runtime/xiaoyou_runtime/xiaoyou.py` 中的 `reply_schema()` 与 `lane_schema()`。
界面改名不会修改 Python 模块、安卓包名、`xiaoyou` 等 JSON role 或 BLE 设备名
`Claude-XXXXXX`。

用量入口位于连接与设置：显示当前来源电脑、连接状态、订阅窗口及
重置时间、帮手模型和档位、数据更新时间。没有数值就明确显示未知；真实 0% 仍显示 0%。
断线时保留的数据明确标为缓存。手动刷新在后台执行，切换电脑后丢弃旧来源的结果。
对声明了 `usage` 的硬件，当前来源暂无数据时也会发空列表，清除上一台电脑的旧数值。

## 哪些内容会到设备上

| 手机上 | 设备上 |
| --- | --- |
| 在聊天框里发给DS的一句话 | 第一屏：你说的话、DS在想、她把活儿交给了谁，然后是一两句简报 |
| Runtime 上的卡 | 第二屏只翻对话（DS自己答的）：最近 8 张，加上所有还在做的和第三屏单子上的；任务的卡在分开显示的固件上带的是这件事最近的来回（最多 480 字节），给第三屏进去的那一页看。每张是这件事的第一句话和DS最新的话（前 959 字节；完整的来回留在手机上） |
| 交给帮手的事 | 第三屏：最多四件，在做的在前（谁在做、做了多久、最近两步，工具名和命令原样），固件声明了 `threads` 时后面接着最近做完的（结论的简报）；顶栏的“在做 N”。在第三屏按住说的话带 `pin`，App 原样交给 Runtime：一定归到选中的那件事 |
| Runtime 发现的电脑端独立运行对话 | 同样的任务和卡片页面显示 agent、项目、状态和最新活动；点开任务显示最近可见的需求与回复片段（最多 480 字节）。继续和停止会话仍在电脑上完成；实时权限桥中的审批是独立回传通道 |
| 帮手要做的、需要确认的操作 | DS发问，谁要做什么原样显示；`确认键` 可以，`下键` 不行，回答交回 Runtime |
| 在设备上录的一段语音 | 和打字的消息一样；Runtime 识别出来之后，设备和聊天框里都会显示听到的内容 |
| 当前选中的 Runtime 上的 agent | 菜单里的“帮手”页（前四个） |
| 当前选中的 Runtime 上的用量 | 第四屏：订阅窗口、重置时间、帮手模型和档位；数据未到和断线时仍保留这一屏 |
| 已登记来源的一条安卓原生通知 | 菜单里“通知”页的一条；它与桌面 Runtime Hook 是独立来源 |
| 还没被划掉的通知 | 空闲的第一屏会写出有几条 |
| 同时带有“允许类”和“拒绝类”按钮的通知 | DS发问；`确认键` 触发允许按钮，`下键` 触发拒绝按钮 |
| 没有新消息 | 每 10 秒一次保活，让设备保持连接 |
| 电脑上指定了一版设备固件 | 设备显示“在换新样子”和进度，换好后自己重启，见下面的[设备固件](#设备固件) |

设备在 App 自我介绍时声明它认识什么。声明了 `cards` 的固件支持卡和任务页面，上面这些都发；
只声明 `chat` 的是上一版，App 只发当前这一轮，不发卡和任务；两个都没声明的更早的固件，
App 退回到最早的做法：发说明行，并把最新一条消息的全文作为 `turn` 事件发过去。授权
在三种固件上都能问。

Runtime 早于 0.5.0 时没有卡和授权：App 的日志里会说它是旧版，聊天照旧一句一句显示。

### 对话和任务分开（0.8.0）

在任务页发送的话带任务编号和 `pin`，接着原任务继续。任务 `pin` 需要
Runtime 0.5.3；更早版本会忽略它，仍由 DS 判断话归到哪件事。

### 用量、档位和任务历史（0.9.x）

- **设置页最上面的“用量”**：Runtime 报来的每个订阅账号 5 小时、本周各还剩多少、什么时候
  重置、数据从哪来，以及跑在它上面的帮手和它们的模型。设备声明了 `usage` 时，同样的内容
  发给设备的第四屏（有变化就发，另外每 60 秒校准一次）。
- **档位按钮**：输入框旁边，点一下在“默认档 / 低档 / 中档 / 高档”之间换。选了档的那句话
  带上 `effort` 发给 Runtime，发出去之后回到默认档。
- **任务详情**：一行写清谁做的、用的哪个模型、哪一档、大约花了多少额度。
- **给设备的任务历史**：设备声明了 `past` 时，最近做完的事（最多五件，按天分组）单独发
  （`past`）；设备打开一件手里没有卡的旧事时来要（`want`），App 把那张卡补发过去。
- **设备内存**：设备报的剩余内存（`fw info` 里的 `heap`、`low`）转给 Runtime，
  `firmware status` 里看得到。

能转发的只有通知里已有的内容。某个助手是否会为云端会话发通知、通知是否带操作
按钮，取决于那个助手的 App，目前没有验证过。

### 电脑上正在运行的对话

已配对 Runtime 开启电脑端观察后，在 Codex 和 Claude Code 中独立运行的对话会出现在
各自的帮手页。每一项沿用电脑侧栏里的会话标题，同时显示电脑来源、项目、当前状态和最新活动。
App 原样展示 Runtime 提供的标题，电脑上重命名后更新同一任务。如果暂时无法取得电脑端标题，
会显示最近需求或会话标识，并明确提示这是回退标题。超过 Runtime 的 200 字符上限时会提示
标题有所省略。硬件任务和历史列表的 47 字节 UTF-8 标题栏优先展示同一个标题，按字符边界截断，
不再在标题前占用空间拼接项目和来源。所有接入的 agent 都遵循这套标题规则，App 不另行生成
标题或总结。点开可以查看最近的用户需求和
Codex 或 Claude 的可见回复，并使用实际助手名称。Runtime 提供最近最多 20 条消息，
每条最多 4,000 字符、每个会话的 UTF-8 内容总量最多 32 KiB；App 标明最近片段，
并提示内容有所省略。设备通过现有的 cards/tasks 蓝牙消息收到最近需求与回复片段和状态，
回复总量仍限制在 480 字节内。这些卡是只读的：继续和取消仍需在电脑上操作，在设备上
选中电脑任务后说话也不会远程控制它。安装并信任 Codex 或 Claude Code Hook 后，实时
`PermissionRequest` 可以独立通过手机或设备回答。只有权限通知或状态、没有回传通道时，
仍提示在电脑端确认。本轮结束不代表整个项目已完成。App 不显示私有推理、
工具输出或尚未被记录为可见消息的回复。这里提供最近对话内容，并非完整对话归档或逐字实时输出。

状态采集或手机与 Runtime 的连接中断时，任务仍留在当前列表，显示状态未知，保留最后采集到的内容，不计时，
也不会移入完成历史。连接恢复后 App 重新读取 Runtime 上的状态。声明 `desktop` 能力的
固件会分别显示未知状态和本轮结束；旧固件收到停止状态的兼容值，卡片回复中写明实际
状态，不显示运行计时。可发现哪些本地会话以及如何开启，见 Runtime 的
[电脑端观察说明](../runtime/README.zh_CN.md)。

## 安装与设置

每次推送改动到 `companion/`，GitHub Actions 都会构建一个调试版 APK，并挂到名为
*Pocket Hub debug build N* 的预发布版本上。在手机上下载 `pocket-hub-debug.apk`，
并允许浏览器安装应用。

在 App 里依次：

1. 授权蓝牙。
2. 在系统设置里给本应用开启通知使用权。
3. 连接。设备屏幕显示六位配对码时，在手机上输入。

要和DS说话：在同一个网络里的电脑上启动 Runtime，在那台电脑上运行
`python3 -m xiaoyou_runtime --pair`，把打印出来的那一行（`http://<地址>:<端口>#<令牌>`）
粘贴到 App 里并添加。可以添加多台电脑：点一下选择由哪台回答，长按删除。App 在手机上保存
最近 20 轮对话，发消息时把最近的几轮交给当前选中的 Runtime，所以换电脑后对话能接着聊
（哪些带得过去、哪些带不过去，见 Runtime 说明里的“多台 Runtime，一段对话”）。卡不存在
手机上：它们在 Runtime 那边，App 启动或者换电脑之后从头再取。

设备同一时间只接受一个蓝牙连接。连手机之前，先让它和 Claude 桌面端断开（或者
离开那台电脑）。

## 交互与动效（0.22.0）

参考 Claude 移动端的交互整理了一轮，只改手机上的显示和手势，Runtime 接口不变：

- **聊天和任务页只追加**：新消息接在后面、从下面浮上来，旧消息不动，滚动位置不跳；还在回的那条
  只往自己那一行里加气泡。只有加载更早的消息、消息被删或顺序变了才整页重画。任务页的步骤、对话、
  回复中的话分三段各自更新。
- **回复状态标记**：最后一条回复下面，在想、在写都是一个白气泡里三个点依次跳的「正在输入」（8 秒以上
  旁边写在等什么），说完换成一个静止变淡的星芒，旁边是「复制」和「重新问」（把上一句原样再发一次）。
- **输入框按钮四种样子**：聊天页没字时是按住说话（松开发送，滑出按钮取消）；有字时是发送；

在“连接与设置 → 快速审核”进入，或点击待确认横幅。页面标明所选电脑，展示待审核工具操作

模式默认手动。App 0.21.0 配合 Runtime 0.13.0 可选择“持续开启，直到手动关闭”、15 分钟、

页面打开时每三秒刷新，并始终绑定原来的电脑；电脑被移除或
所选来源改变后，应在目标电脑下重新打开。

Runtime 0.12.0 提供基础快速审核和临时一小时模式；缺少时长能力声明时，App 0.21.0 保留原有

### 发布一次 App 改动（开发者和 AI agent）

`companion/android` 的每一次完整改动都这样送到主人手机上，不再发 APK 文件让主人自己装：

1. **加版本号**：改 `companion/android/app/build.gradle`，`versionCode` 加 1，`versionName`
   修问题加末位、加功能加中间位。手机按版本号比较；忘了加只有在安装包不同、而且发布得比手机上那份
   装得晚时才会提示。
2. **编译和测试**：在 `companion/android` 下用 JDK 17 和 Android SDK 运行
   `gradle testDebugUnitTest assembleDebug`，两样都要通过，没通过不发布。安装包在
   `app/build/outputs/apk/debug/app-universal-debug.apk`，旁边有 Gradle 写的 `output-metadata.json`。
3. **发布**：在跑着主人 Runtime 的那台电脑上（在 `runtime/` 下）：

   ```bash
   apk_dir=../companion/android/app/build/outputs/apk/debug
   python3 -m xiaoyou_runtime app publish "$apk_dir/app-universal-debug.apk" \
     --variant "arm64-v8a=$apk_dir/app-arm64-v8a-debug.apk" \
     --variant "armeabi-v7a=$apk_dir/app-armeabi-v7a-debug.apk" \
     --variant "x86=$apk_dir/app-x86-debug.apk" \
     --variant "x86_64=$apk_dir/app-x86_64-debug.apk" \
     --note "主人看得懂的一句话"
   python3 -m xiaoyou_runtime app status
   ```

   发布默认把所有提供的 APK 上传到 GitHub Releases（主人已授权公开托管）。文件名包含
   内容哈希，同版本重发不会误用旧文件。`--github ABI,...` 可以限定架构，`--local-only`
   明确跳过上传；上传失败保留原本机发布。这里只传文件，不推送 Git 提交。语音包仅在
   资源有变化时重新发布：

   ```bash
   python3 -m xiaoyou_runtime app pack speech ../companion/android/app/build/phone-speech/assets/asr
   ```

   资源包按文件校验值存放和上传：没变的文件不重复上传，手机也只下载变了的文件。

   备注会显示在手机上，写给主人看的改动，不要写提交术语。发布只是替换正在运行的 Runtime
   提供的文件，不用重启。Runtime 比这个功能旧（没有 `/v1/app`）时要重启一次，而且只在没有任务在跑时重启。
4. **告诉主人**版本和备注，下次打开 App 会提示（或在「连接与设置 → App 更新」里手动查）。
   主人确认装好之前，要说明手机上的安装还没验证。
5. **提交；推送要等主人说**。发布不等于推到 Git，推到 Git 也不等于发布。

位置参数中的 APK 是不给出架构的旧 App 所用的默认包。除非这台私有 Runtime 上所有旧手机
都确认支持某个架构，否则默认使用通用包。已确认的 ARM64 手机可以将 ARM64 包作为默认，

先在空闲时重启支持分包和 Range 的 Runtime，再发布分包。CI 下载仍保留原来的通用包文件名。

改动同时要动 Runtime（App 要调新接口）时，先重启 Runtime 再发布 App，否则新 App 会碰上旧 Runtime。
带这个功能的第一版（0.11.0，版本号 17）要手动装；手机上还是更旧的版本时，要再手动装一次。

## 设备固件

配套固件和 App 使用原有 `avatar-whale-v1.png` 像素大头。固件将六种表情编译为
60×60 索引图集（21,856 字节 Flash，无解码缓冲），保留已有的 120、40、60 显示
像素尺寸，以及睡觉、待命、忙碌、询问、开心、出错六种情绪。睡眠帧使用单独的圆脸
修正版，眉毛平缓；睡觉、待命、询问、开心每 3.6 秒轻微起伏一轮，首页最大移动 4 像素。
`hub` 应答新增 `desktopApproval: true`。心跳中的 `prompt.actionable` 默认 `true`，
保持兼容；为 `false` 时，新固件显示“请在手机或电脑确认”的只读提醒，不提供批准动作。固件没有声明
`desktopApproval` 时，App 将这种请求作为文字摘要发送，不发送可操作 prompt。
实际审批仍使用原有 `permission` 应答，并按来源请求路由。
来源或操作放不下时只截短并注明，仍可在设备上回答；能不能回答只看 `actionable`。

设备只连着手机，所以新固件由手机转交：电脑（Runtime）上留着每一版，并记着设备该是
哪一版；App 连上设备时问它现在是哪一版并告诉电脑，之后一直盯着电脑那边。两边不一样
时，App 取来那一版的镜像，核对 SHA-256，经蓝牙传给设备，大约一两分钟。设备重启后
App 连回去“认可”新固件——设备三分钟内等不到这一句就会自己退回上一版——再把结果
告诉电脑。连接中途断了，重新连上后接着传，不从头来。电脑要的那一版正好还在设备的
另一个槽位里时不用传，设备几秒钟就切回去。

界面上“设备固件”那一栏显示现在的情况。点“看看电脑上留着哪些版本”，再点其中一版，
就是把设备换成那一版（会先问一句）；装上之后不能再经蓝牙换的旧版本不提供。平时不用
来这里：对设备说一句话，或者在电脑上运行 `firmware restore`，效果一样。

需要设备上已经是带这个功能的固件。更早的固件会被认出来，App 会说要先插线刷一次。
协议见 [`docs/claude-pocket.zh_CN.md`](../docs/claude-pocket.zh_CN.md#经蓝牙换固件)，
电脑那边见 [`runtime/README.zh_CN.md`](../runtime/README.zh_CN.md#设备固件)。

## 隐私

已登记来源的通知文字只保存在内存里，只通过加密的蓝牙连接发给已配对的设备，不写入
存储，也不经过网络。其他 App 的通知一律忽略。

App 只在一件事上用到网络：和你配对的 Runtime 地址通信——把你在聊天框里输入的话发
过去，读回回答和卡（开启观察后也包括最近可见的电脑端对话内容），把你对授权的回答和“取消这件事”发过去。设备上录的语音也走这条路，不在手机上保存。这条连接是明文 HTTP，同一网络里的人能看到
内容，只在你信任的网络里使用。各台
Runtime 的地址和令牌，以及最近 20 轮对话，保存在 App 的私有存储里。

设备固件也走这条明文 HTTP 连接从 Runtime 下载，App 只核对它和清单里的 SHA-256 一致；
镜像没有签名。所以能改动 Runtime 上固件清单的人，就能让 App 把任意镜像写进设备。
