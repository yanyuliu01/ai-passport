## Runtime 生命周期与安装版本核对（0.1.25）

通过菜单退出小鱼或 Cmd+Q，会停止该 App 启动的 Runtime 子进程。退出现在先等待
最多五秒，超时后终止并做最后一次有界检查。Windows 会停止其拥有的进程树。
App 只是连接到的、原本已经运行的独立 Runtime 不会被终止。退出也会隔离迟到的
服务启动和恢复。关闭窗口仍沿用后台运行行为，与退出 App 分开。

主人截图显示从旧发布目录运行的 0.1.19。提供的 0.1.23 DMG 已只读挂载，
其 Info.plist 确认为 0.1.23。旧 App 尚未退出时，单实例机制可能将再次打开
转给旧程序。应退出旧 App，再打开已安装的当前版，并核对界面显示的版本，
不能仅凭 DMG 文件名判断实际运行版本。

退出账号后始终返回当前首次使用流程，兼容带有旧配置确认标记的资料。

## 首次使用时选择帮手（0.1.23）

流程为登录账号、扫描并明确选择本机帮手、填写 DeepSeek Key、收到真实问候。
扫描区分命令行程序可运行、本机配置存在和登录状态。先支持 Codex、Claude Code；
内置 Pi 可选。未登录的助手需先在该助手中登录再扫描；登录状态未知时明确标注，
实际任务仍需验证。不会自动勾选，也可以不接入帮手继续使用。WorkBuddy 和豆包工作
属于后续接入范围，目前没有可选适配器。

所选帮手的启动命令与审批边界写入新建本机 Runtime 配置，中断恢复保留选择；
重试不会改动此前尝试已经配置好的服务中的帮手。Codex 默认 gpt-6.1-sol，
Claude Code 默认 Sonnet。扫描只执行有时限的版本和登录状态探测，不调用模型、
返回原始登录输出、导入历史或复制凭据。扫描常见原生 CLI 安装位置；Windows npm
启动器解析其所属软件包登记的 bin，使用内置私有 Node 启动，不经过 cmd.exe。
JavaScript CLI 的 shebang 同样使用该 Node，兼容 GUI 的 PATH 中没有系统 Node。
只有桌面应用而没有可运行 CLI 时，不会误报为可接入帮手。

安装包包含私有 Python、Pillow／原生 Runtime 依赖、Node、DSH 和 Pi，
随小鱼安装即可使用，无需另装开发环境、全局 Python／Node 或修改系统 PATH。
打包后逐文件比对所选原生 Runtime 的全部 Python／依赖；Node 和助手资源另有完整
哈希清单门禁。Windows 原生安装验收按主人安排稍后进行。

验证：154 项桌面测试及启用工具链的完整仓库门禁通过。打包 Mac 窗口覆盖帮手

首条回复、重启恢复和正常退出。该验收夹具使用合成 CLI 和模型。另一次只读扫描

## 无开发环境首次使用（0.1.22 源码）

默认流程是登录小鱼账号、填写自己的 DeepSeek Key、收到第一条回复。
Runtime、Node、DSH 和 Pi 都随包提供；帮手检测和高级连接选项不阻塞这个流程。
Pi 预登记为未启用，可在帮手设置中明确启用；不开放文件和命令工具。
已有配置的用户保留高级设置入口。

按钮明确告知并授权两次简短付费调用：先用固定短消息验证 DeepSeek Key，
再通过真实本机 Runtime 和消息 API 发出问候。Key 验证区分认证、余额、
服务端和网络失败。只有成功的 Key 才存入系统安全存储，并按账号空间隔离；
旧 Key 在登录可能改变空间之前绑定原主人。不会把原始服务端诊断或 Key 返回界面。
只有收到非空的 Runtime 最终回复才完成，不把健康检查或传输回执当作成功。
问候保留在主对话；接收回执丢失时，重试沿用同一个持久客户端编号，
重启后续接已记录的请求，不再自动调用 Key 验证。终态失败需要用户明确重试。
退出账号会隔离旧回调、凭据和聊天缓存的界面投影。

首次启动先用 `--version` 准备内置 Runtime，不创建配置或身份。
准备过程有独立、有界的状态，不延长聊天时限，也不计为有意义首回复。
原有服务启动时限保持不变；服务晚启动时保留原进程和计划中的账号空间，
由后台继续完成配置，不再创建另一个 Runtime。准备过程被中断时，
只保留验证成功的安全存储 Key，并从已保存阶段恢复。
启动或连接已有服务之前先核对空间，避免先启动另一账号的服务再拒绝。

Windows 使用固定校验值的嵌入式 Python/Pillow 和私有 Node，复用相同状态机。
跨平台生成的安装包只是候选，不代表 Windows 原生安装验收。
真实 Key 的界面渲染时延、全新系统用户安装、签名/公证及公网恢复仍需分别验收。
旧安装包和配置保留用于回退；重试配置不清空凭据或历史。

## 本机服务稍晚启动后的恢复（0.1.10 源码）

客户端管理的 Runtime 在首次启动等待超时后若仍在启动，既有监督器会继续检查同一进程。
服务就绪后，仅在认证身份已经确认的情况下重新连接。不另起进程，不确认新身份，也不反复
替换健康连接。初次启动与恢复不能并发，关闭后的迟到响应不能重新连接客户端。被信号终止
的子进程按已退出处理，保留十分钟最多重启三次的原有限制。外部服务仍不归客户端管理进程。

原启动等待和监督周期不变。本次修复稍晚就绪后的恢复，不代表冷启动已足够快、真实模型
首答已在三秒内，也不代表已安装桌面版本验收通过。

## 统一请求回复（0.1.9 源码）

Runtime 声明 `sync_requests_v1` 后，待处理的已受理请求加入原有同步订阅。新增请求只取消空闲的 sync 读取，不取消同时进行的操作核对，也不清除持久化发件箱。当前正式回复快照沿用原修订号，不推进历史游标。请求状态暂不可读时仍保留为已受理，不会重新提交。旧 Runtime 继续使用支持的逐消息读取；Runtime 回退时，先重新核对身份和能力再切换读取协议。feed／wait／stream 服务端适配接口保留到已安装客户端迁移和版本门槛允许 R8 删除时。本源码改动不代表真实模型时延验收或桌面已安装版本更新。

## 被打断的回复（0.1.8 源码）

主人插话打断的回复保留已经说出的文字；Runtime 标记了中断（`presentation.interrupted`）时，
气泡下面显示“已打断”。状态行规则与 Android 通过共享夹具保持一致。

## 人工核对版本检查（0.1.8 源码）

请求和定时操作的确认都携带主人实际看到的记录版本。提交前操作发生变化时，桌面端
不发送确认，而是重新读取操作并清空旧选择。已保存的确认在回执丢失后仍按原正文和
原选择重试，不会套用新版本。已有核对记录、但本客户端没有保存原重试内容时，页面
提示回到保留原确认的设备处理，不另造核对身份。这些源码检查不代表手机或真实多端
验收通过；Runtime 接口和已保存的确认正文格式不变。

桌面端还会在发送 POST 前，把待核对操作的原线路和凭据保存到现有的客户端加密存储。
重开客户端或升级设备凭据，不改变该次重试所用的身份。原凭据被撤销时停止，不换
另一个身份尝试。安全存储缺失或线路改变时保留确认，并提示恢复；旧版只保存正文、
没有身份元数据的待重试记录不会自动归到新身份。恢复时应同时保留客户端数据库及其
系统保护的安全存储。回退到旧客户端代码后，旧版不会执行这些新增重试检查。

连接替换或客户端停止时取消对应核对请求，迟到回执不能清除已保存的确认。前一份
提交未完成时拒绝重复提交。中继自身重启或升级凭据后，也沿用原 HTTP 身份，并把
请求限定到指定 Runtime。凭据不会进入中继消息或明文缓存字段。中继保留身份元数据
供后续相同确认重试；旧版中继不具备此保护。源码测试使用合成数据，已安装客户端和
Android 恢复仍需单独验收。

## 当前回复送达（0.1.7／Runtime 0.23.1）

已接收请求会保留等待状态，直到助手回复明确结束。只同步到用户消息，不会移除加载提示。
历史尚未补拉到的已接收请求也显示等待提示，重启或临时断线后继续保持，并显示连接错误。

Runtime 的轮询／接收结果新增 `message_snapshot`：提供权威日志里的用户和回复记录、
原始修订号、Runtime／主体身份和 epoch。桌面端按原有修订规则写入缓存，不推进历史游标。
旧历史仍在分页时，当前回复可以先显示；后续重放不会重复用户消息，也不会用生成中片段
替换完整回复。缓存读取复用 epoch 查询，窗口通知合并为 100 毫秒一批，减少补拉期间的
重复工作。旧 Runtime 保持等待提示，通过常规同步取得回复内容。

验证：58 项桌面测试及隔离的源码／打包 Mac 窗口通过。窗口检查已接收等待、仅同步用户消息、
带等待请求重启、离线反馈及历史补拉受阻时显示当前回复。源码和打包窗口的模拟恢复分别耗时 785／795 毫秒，
不属于真实模型首答时延测量。已安装的 0.1.7 Mac 窗口也从现有用户缓存中恢复并显示了
先前卡住的已接收请求；历史仍在补拉，发件队列已清空，没有重新提交消息。已安装客户端、手机及 Codex／Claude 原生窗口仍须分别验收。

## 常开电脑内置通信节点（0.1.5 / Android 0.30.1）

连接设置新增“让这台常开电脑承接通信”。确认本机 Runtime 后，主动启用节点，
选择 TCP 端口（默认 18795），有公网 IP／域名和外部端口后填写入口地址。
关闭窗口继续后台运行；正常重启客户端会恢复已启用的节点及原身份。
退出客户端、电脑休眠或关机会中断这个入口；登录自启动仍由用户主动开启。
中继与 Runtime 并行运行，不会暴露或重启 Runtime 的 HTTP 服务。
停止节点时恢复原先配置的外部入口（若有），保留信任设备、历史缓存和待确认请求编号。

本机用 selfsigned 5.5.0 生成 P-256 TLS 证书，私钥、随机入口密钥和房间编号
保存在 Electron 系统加密存储中。邀请包含证书 SHA-256 指纹；Android 0.30.1
和桌面 0.1.5 在发送 HTTP 凭据前校验它，因此可直接使用公网 IP，不强制购买域名
或申请公共 CA 证书。已有普通 WSS 入口继续使用系统 CA 校验；HPKE 仍独立保护
端到端内容和设备身份。指纹不符、未生效或过期的证书会被拒绝。
证书有效期一年，自动续期与设备撤销后续完善；不能静默更换身份或跳过证书校验。

承接节点的电脑通过本机回环连接，不依赖路由器回流；该内部地址不会进入邀请。
未填公网地址时不能生成节点邀请。界面区分本机监听、公网地址电脑侧探测、
手机实际连通；电脑侧探测成功不等于手机异网实测通过。

常开电脑仍需要公网入站条件。使用路由器公网 IPv4 时，把一个外部 TCP 端口映射到
电脑的固定局域网地址和监听端口，仅开放相应中继端口。使用全球 IPv6 时放行相应
IPv6 防火墙端口，节点双栈监听。不会自动修改路由器、防火墙、VPN 或 Tailscale。
当前 Mac 尚未验证公网入站，也未完成手机蜂窝网络测试；可能仍需路由器／运营商
配置，或换一台确实可从公网访问的常开电脑。此增量提供集中入口，不包含自动打洞、
完整虚拟局域网或节点自动切换。

公网地址变化后需要更新入口并重新配对受影响设备；地址自动发现与传播尚未实现。
测试新入口期间保留旧入口。原桌面 0.1.3 和 Android 0.29.0 可保留原配置与缓存，
但不能连接这个新的自签名节点；该角色两端均需支持指纹的新版本。
手机安装、真实公网恢复、Windows 原生运行和模型首个有效回答 ≤3 秒仍待验证。
本地 WSS／Java 协议与原生 Mac 生命周期证据记录于
`build/xiaoyu-node-validation.json`。

本轮验证：Mac arm64 构建及 DMG 完整性通过；52 项桌面测试、161 项 Android

## 独立手机通信与扫码配对（0.1.3／Android 0.29.0）

当前优先级是不同网络之间的手机通信，不依赖 Tailscale。电脑生成两分钟本机二维码；
Android 提供「扫码连接电脑」，显示手机指纹供核对，等待电脑明确批准。一个手机保留最多
八台电脑连接；新增配对不覆盖旧设备及固定公钥。独立通道使用主动出站 WSS 和桌面同一套
认证 HPKE：X25519／HKDF-SHA256／AES-128-GCM。Runtime 令牌仅留在电脑，手机配对资料及
待发写入意图通过 AndroidKeyStore 的 AES-GCM 存储。配对不调用供应商或模型。

文字、普通轮询／同步、审批、任务补充、语音／图片上传及有大小限制的附件读取，均通过
有身份校验的中继白名单。语音／图片／附件单次上限为 2.8 MB，超限明确报错。长轮询收敛为

## 原生 Runtime 包和安装程序

PyInstaller Runtime 必须在目标 OS/架构构建，Mac Python 包不能放进 Windows 安装包。
打包钩子验证架构和 Runtime 源码摘要，拒绝缺失/过期的包。它从最终的
`extraResources` 映射读取 Runtime 目录，包含平台专用配置；必须恰好有一个
完整目录映射到 `runtime`，重复、嵌套或带过滤器的映射会被拒绝。若设置了
`XIAOYOU_RUNTIME_BUNDLE`，它必须解析到同一目录，不能校验另一个包后把旧包
装入安装程序。另有 Windows 路径，
在构建机上仅组装官方 Windows 二进制而不执行，仍须通过 Windows 原生验收。

```bash
python3 -m venv .runtime-venv
.runtime-venv/bin/python -m pip install -r requirements-build.txt
.runtime-venv/bin/python tools/bundle_runtime.py
npm run bundle:agents
npm run package:mac
```

与 Python 3.11+。也可手动让 Python 步骤使用 `.runtime-venv\Scripts\python.exe`，再运行
`npm run package:win`；当地可能用 `python` 命令代替 `python3`。
生成的 Runtime 文件和安装包已由 Git 忽略。不得包含真实 Runtime 配置、状态、
密钥或 CLI 私有目录。Codex/Claude 程序和登录仍由外部提供；DSH/Pi 则包含在独立的私有助手包中。构建锁定 Pillow 11.3.0，

```bash
node tools/download_windows_electron.mjs

python3 tools/release_manifest.py
```

该预览配置跳过 Windows 可执行文件资源编辑/签名。本轮已组装 Python 包，但
Windows Electron 下载未获执行授权（`owner denied`），没有生成 Windows 安装包。
不能换下载路径绕过拒绝。Windows 原生模块加载、安装、provider 就绪和界面仍未验证；
构建脚本仍保留原生 PyInstaller 路径。

普通分发需要适当签名/公证。私有未签名/临时签名包可能触发系统警告，不满足
无额外门槛安装的声明。不能通过关闭系统安全来掩盖该缺口。

## 自建中继

部署者提供至少 32 字符的随机访问口令与公网 WSS 入口。
在 TLS 反向代理之后，以回环监听启动中继：

```bash
npm run build:main
XIAOYU_RELAY_TOKEN='<random-access-token>' npm run relay
```

默认监听 `127.0.0.1:8795`，CLI 拒绝公网明文监听。TLS 代理转发 `/v1/connect`，
包括 WebSocket upgrade。部署前在实际主机配置资源限制和服务监督。
中继包含认证、房间隔离、帧/缓冲/连接/速率限制及心跳清理，不运行模型或任意本机命令。

部署者私下准备入口 JSON，包含 `url`（WSS origin）、`token`，以及可选的随机
32 位十六进制 `room`。在“设备与连接→高级连接设置→导入通信入口”导入，
不提交这些凭据。配置一次后，普通加入端通过邀请获得连接设置，无需填写地址/口令。
只有回环测试入口允许 `ws://`。

本源码没有部署或购买中继。已有常开电脑必须先证明入站可达才能承载入口，
单纯常开无法解决 NAT/防火墙。

## 数据与恢复

客户端数据位于系统用户数据目录。凭据/密钥种子使用系统保护存储密封，当前
聊天 SQLite 缓存没有单独加密，需要保护 OS 账号和磁盘。
关闭窗口仍在托盘/菜单栏运行；“退出”只停止本进程自己启动的 Runtime 子进程，
不停止外部管理的 Runtime。“登录时启动”由用户在界面明确开启。

不要通过删除用户数据目录修复连接。升级时一起保留数据库与系统密钥访问。
接收结果未知的请求保留原 Runtime 和 `client_id`；任务来源、连接代次受到约束，
不能因来源不可达就改去其他电脑重新执行。两台电脑都不可达时的在线服务与独立
密钥恢复不属于日常常开基线。

隔离原生测试时，在启动前将 `XIAOYU_DESKTOP_TEST_DATA` 设为新的临时目录，
并设置 `XIAOYU_DESKTOP_SKIP_DISCOVERY=1`；打包程序也支持，避免冒烟测试碰到
日常资料。测试资料中不要导入真实配置或登记登录启动。
