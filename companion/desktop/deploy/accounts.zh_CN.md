# 账号发现与默认公网中继

桌面 0.1.13 新增主人自建的账号和设备发现服务。每台电脑继续运行自己的 Runtime；
账号负责发现同一主人的电脑，不把新电脑变成只能遥控老电脑的客户端。
原有 mesh 身份、任务归属、记录同步和指定共享文件夹规则继续生效。
新请求优先交给本机 Runtime；已接受的待处理请求仍绑定原执行端。
主对话的归属和转发仍遵循 Runtime 的 mesh 配置。

## 首次使用

在已有电脑连接原本的本机 Runtime，在设置中创建小幽账号。桌面已内置公网入口和证书指纹，
不需要域名或导入 JSON。这些是公开的路由信息，不包含访问密钥。
小幽账号独立于云厂商、OpenAI 和模型服务商账号。

新电脑登录同一账号后，直接检测、配置自己的帮手和 Runtime，原电脑无需在场或在线。
客户端从账号的加密恢复备份中取回原互通身份，同账号电脑通过认证后的设备发现自动连接。
新建的私有 Runtime 配置使用该身份；模型密钥和帮手执行留在本机。
不会为了改身份而覆盖或重启既有 Runtime 配置；遇到不同空间时保留原配置，明确报告需要迁移。
0.1.11 创建的旧账号须先在原电脑登录一次建立恢复备份，之后换电脑不再需要原电脑在线。

手机继续使用原有“扫码连接电脑”，扫描桌面“添加手机”的二维码。
二维码携带私有中继连接和证书指纹；Android 邀请协议未改，本轮未修改 Android 安装包。
登录账号后，二维码生成按当前账号邀请校验；旧配对邀请继续校验其原入口。
使用数字 IP 时仍保留 TLS 和端点 HPKE 加密。

## 保留的边界

账号认证成功即授权新电脑加入，不再要求另一台电脑确认。手机扫码仍沿用原有的明确确认。
客户端用密码派生的 scrypt 密钥（N=32768、r=8、p=1）和 AES-256-GCM 加密互通身份，
把账号 ID 与空间绑定为认证数据。恢复备份首次写入后不可替换，中继重启后保留；
无效或被改动的密文恢复失败，不另建身份。服务器保存密文，不保存明文互通身份。
这不是零知识密码协议：登录时密码经固定证书的 TLS 传给主人的服务器，
因此需要信任该服务器作为账号认证方。它能看到设备公开身份及路由元数据；
对话仍由端点加密，账号服务不存档聊天。
密码至少 8 位，以带随机盐的 scrypt 哈希保存，会话令牌仅保存哈希。
桌面通过系统安全存储保存恢复密钥与登录令牌，不保存密码。
登录有效期 30 天，每个账号最多 16 台电脑同时登录；私有部署最多 32 个账号，
认证并发和速率有上限。目前没有修改密码、邮箱找回或密码重置流程；
以后若加入改密，必须重新加密原恢复备份，不得悄悄生成另一身份。

每个账号独立拥有中继凭据和房间，不能跨账号房间访问。
账号功能之前的中继凭据继续工作。账号通信使用独立的本机配对数据库和加密密钥，
保留原配对、待处理请求。退出会撤销这台电脑的登录会话并停止账号连接，保留本机历史；
不会撤销其他已加入设备，也不会轮换二维码共享的中继凭据。

远程文件访问沿用现有 mesh 和附件规则，只共享明确配置的文件夹及已有授权附件接口，
没有新增任意磁盘或整个 Runtime 状态目录导出。模型密钥不会自动复制；
原有 mesh.share.env 白名单继续生效。来源离线时保留绑定来源的待处理请求，
不会悄悄换另一台电脑执行。

## 部署与恢复

编译桌面主进程，部署 dist-main/relay/server.js、accounts.js、start-ip.mjs、
锁定的 ws 依赖，以及重命名为 compose.yaml 的 compose-ip.yaml。
保留已有 .env 和 tls，建立仅主人可读、UID 1000 所有的 data 目录。
账号保存在 data/accounts.json；升级时与 .env、TLS 身份一起保留。
固定 IP 模板使用本次部署核验过的镜像 digest，仅发布 TCP443；普通域名模板继续单独保留。

主人的默认入口和证书指纹在 core/account.ts。更换部署或证书，需要更新这些公开值并重新打包。
禁止把私有中继令牌写进源码。账号数据包含密码哈希和元数据，备份须保持私有。
云端只做在线转发和设备发现，不是离线信箱、模型执行器或永久聊天档案。

回退时可恢复旧中继程序和 compose，保留 .env、TLS、账号数据和所有客户端数据库。
旧连接仍可使用；账号连接需要支持账号的中继和 App，旧服务器不理解新账号登录。
重新启用新版本后恢复保留的账号记录，不通过清空数据修复。

## 验证范围

主机覆盖账号房间隔离、错误凭据拒绝、登录限流、原电脑离线时仅凭账号加入、加密身份恢复、
两台真实 Runtime、指定文件复制、绑定来源的 RPC 和原有桌面回归。
Runtime 使用隔离 echo 夹具，不能据此认定真实模型或界面三秒首答通过。
Windows 原生、实体 Android、BLE 和真实用户完整跨网验收均须单独报告；构建部署不代表这些通过。
