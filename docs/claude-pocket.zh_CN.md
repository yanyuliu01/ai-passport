# Claude Pocket

Claude Pocket 把 FoloToy AI Passport 变成小幽随身的那张脸。小幽是一只小幽灵，
也是你唯一要对话的对象。设备通过加密的低功耗蓝牙连着手机伴侣：按住按键说话，
她的回答出现在屏幕上；她把活儿交给别的 agent 时，屏幕上能看到谁在做、做到哪一步；
agent 要做需要你确认的操作时，设备上弹出来问你。

这条连接使用 Anthropic 在
[`anthropics/claude-desktop-buddy`](https://github.com/anthropics/claude-desktop-buddy)
公开的 *Hardware Buddy* 蓝牙协议，并为手机伴侣加了一小段扩展。不用扩展时，同一份
固件仍然可以作为 Claude 桌面端的伴侣使用（开启了开发者模式的 macOS 和 Windows；
Anthropic 把这个蓝牙桥定位为面向创客的功能，不是正式支持的产品功能）。

## 功能

三屏，`确认` 短按轮着切；顶栏中间的三个小点表示现在在第几屏。

| 屏 | 显示什么 |
| --- | --- |
| 第一屏 形象 | 大的小幽和她此刻在干什么：在听写、在想、把活交给了谁（一封信从小幽飞向那个 agent 的名牌，旁边在计时）、说完了（一两句简报）、没成（原因）。空闲时写着后台有几件事在做 |
| 第二屏 对话 | 只放对话，也就是小幽自己直接答的；交给帮手的事不在这里翻（刚说的那句交给了帮手时，这一屏只写“这件事交给谁了，在下一屏看”）。一屏一件事：有自己的一张卡——你说的那句和小幽最新的话。顶上一条是这件事现在怎么样；下面一行小字是第几件、几点开始的、谁做的 |
| 第三屏 任务 | 交给帮手的事，最多四件，在做的在前，后面是最近做完的：谁在做、标题、做了多久（或者“等你点头”“排队”“好了”“没成”“取消了”）。下面是选中那件的最近两步，工具名和命令原样显示；选中的是做完的事时，下面是它的结论（简报）。短按 `确认` 进到选中那件事自己的页面：它最近的来回（你后来说的、小幽答的，从最新的那头看起），`上`、`下` 在里面翻，翻到头换到单子上的上一件 / 下一件；再短按 `确认` 回第一屏 |

| 能力 | 行为 |
| --- | --- |
| 按住说话 | 按住 `确认` 录音，音频经蓝牙发给手机伴侣，见[按住说话](#按住说话)。在第二屏、第三屏按住时，这句话是对屏幕上（或选中的）那件事说的：补充、改要求或取消 |
| 审批 | agent 要做需要确认的操作时，由小幽发问；谁要做什么原样显示；在设备上点头或摇头。弹窗盖住任何一屏 |
| 通知 | 对端发来的最近四条记录，在菜单里。有没看的通知时，空闲的第一屏会写出有几条 |
| 帮手 | 小幽可以把活儿交给哪些 agent（由对端告知），在菜单里 |
| 配对 | LE Secure Connections，设备显示六位配对码 |
| 换固件 | 新固件经蓝牙从手机伴侣传过来，不用插线；装上后没被认可就自己退回上一版，见[经蓝牙换固件](#经蓝牙换固件) |

颜色只回答一个问题：现在是谁在干活。小幽是淡紫色；每个帮手有自己的颜色，同一个
名字的颜色固定不变。绿、红、黄只表示可以、不行和“看一下这个”，不作他用。

屏幕不会自己切换：回答来的时候留在你正看的那一屏。顶栏上的“在做 N”是后台还在做
的事的件数，没有就不显示。

连的是 Claude 桌面端而不是手机伴侣时，第一屏显示桌面端报告的内容：干活时的状态行，
以及最新回复的开头；第二屏是最新的那条回复；第三屏是空的。这种模式下不能说话，
因为桌面端的协议里没有提问和语音这类消息。

## 配对

连手机伴侣（通常的用法）：打开“小幽中枢”App，开始连接，在手机的蓝牙提示框里
输入设备显示的六位数字。见 [`companion/README.zh_CN.md`](../companion/README.zh_CN.md)。

连 Claude 桌面端：

1. 选择 **Help → Troubleshooting → Enable Developer Mode**。
2. 选择 **Developer → Open Hardware Buddy…**，点击 **Connect**。
3. 选择名为 `Claude-XXXXXX` 的设备；睡着时的第一屏和“连接指引”页显示同一个名称。
4. 在操作系统的蓝牙提示框中输入设备显示的六位数字。

绑定之后设备会自动重连。如果列表里找不到设备，请确认设备菜单里的蓝牙是打开的。

## 按键

三个按键分别是 `上`、`下`、`确认`。屏幕最下面一行写着此刻各个键是干什么的。

| 所在界面 | `上` / `下` 短按 | `确认` 短按 | `确认` 双击 | `确认` 按住 |
| --- | --- | --- | --- | --- |
| 第一屏 形象 | — | 到第二屏 | 打开菜单 | 说话，松开发送 |
| 第二屏 对话 | 在这件事里翻七行；翻到头再按，换到上一件 / 下一件 | 到第三屏 | 打开菜单 | 说话，对的是屏幕上这件事 |
| 第三屏 任务 | 选上一件 / 下一件 | 到第一屏 | 打开菜单 | 说话，对的是选中那件事 |
| 菜单、更多设置 | 移动选中项（循环） | 执行选中项 | 回到第一屏 | 回到第一屏 |
| 通知、帮手 | — | 返回菜单 | 回到第一屏 | 回到第一屏 |
| 连接指引 | 滚动三行 | 返回更多设置 | 回到第一屏 | 回到第一屏 |
| 等你点头或摇头的请求 | `上` 翻看说明；`下` 不行 | 可以 | 当作一次短按 | — |
| 取消配对 / 恢复出厂的确认 | `下` 取消 | 确定 | 当作一次短按 | — |
| 熄屏 | 只点亮屏幕 | 只点亮屏幕 | 只点亮屏幕 | 点亮屏幕并开始说话 |

`上`、`下` 没有长按和双击功能：长按在熄屏时点亮屏幕，其余时候不起作用；连按两下按
一次短按处理。电源键只控制硬件电源，固件读不到它。

按键库要等双击的时间窗过去才报单击，所以 `确认` 短按切屏会比按下晚约 0.2 秒。

请求、配对码和二次确认会占据整个屏幕，熄屏时会自动亮屏；你刚问的话有了回答时
也一样。按键只对按下那一刻屏幕上显示的内容生效；如果按键和新请求同时到达，这次
按键会被丢弃，不会套用到新请求上。每个请求只接受一次决定，发送失败会显示为失败，
不会当作已允许。在请求上连按两下 `确认` 只算一次“可以”，不会变成没反应，也不会算
两次。

小幽只负责“问”。谁在请求、要做什么直接来自对端，不会被转述；气泡里放不下的
名称会在说明卡片的开头完整再写一遍。

对话和任务是分开的：第三屏上选哪件，不影响第二屏；第二屏上下翻的时候跳过交给帮手的事。
在第三屏、以及从第三屏进去的那件事的页面里，按住 `确认` 说的话是在选中那件事里面说的（做完的也可以）：它一定归到这件事上，
接着它原来的会话做，不会变成一句新的对话。在第二屏按住说的话是普通对话，屏幕上那张卡
只是给小幽的提示。自己刚说了一句新的话，第二屏
跟着这句话走：它还没有卡的时候显示这一轮本身（你说的话、她在想），卡来了就显示那张卡。
你自己翻到别的卡之后，它就留在你翻到的那张上，直到下一次说话。

菜单里有通知、帮手、屏幕亮度（五档）、蓝牙开关、熄灭屏幕和更多设置；更多设置里
是连接指引、取消配对和恢复出厂设置。亮度在重启后回到最大。

设备自己有话要说时（录音太短、连接还没准备好、蓝牙开关失败），这句话会代替按键
提示显示六秒。

## 文字与字库

所有固定界面文案都是简体中文，集中在
[`main/pocket_text.h`](../main/pocket_text.h)。字库由
[`tools/gen_pocket_fonts.py`](../tools/gen_pocket_fonts.py) 从思源黑体
（Noto Sans SC）生成，见[素材文档](../assets/README.zh_CN.md#字库fonts)。

对端发来的文字（你说的话、小幽的话、帮手的名字、通知、谁在请求以及要做什么）
使用覆盖可打印 ASCII、GB2312 全部 6763 个汉字和常用标点的字库。超出这个范围的
字符（表情符号、仅繁体使用的字、其他文字）会显示为占位方框，不会被丢掉或替换。
超出显示区域的文字以省略号结尾；说明超过 319 字节、回答超过 959 字节时会标注
已截断。LVGL 不处理中文的行首行尾禁则，所以折行后一行可能以标点开头。

## 按住说话

在三屏里的任何一屏按住 `确认`。小幽先说稍等，随后说她在听：音量条会跟着你的
声音动，这就表示麦克风已经在收音。说完松开就发送。之后第一屏和第二屏显示录音正在
路上，直到对端告诉它听到了什么。按下不到约三分之一秒就松开，不会发送任何内容。一段录音到 30 秒
会自动停止并照常发送。

设备只负责录音和传输。把语音变成文字、给出回答都由对端完成：手机伴侣把录音转给
小幽 Runtime（见 [`companion/README.zh_CN.md`](../companion/README.zh_CN.md) 和
[`runtime/README.zh_CN.md`](../runtime/README.zh_CN.md)）。

语音是在桌面端协议之上的扩展，对端没有声明之前是关闭的，所以 Claude 桌面端永远
不会收到它不认识的数据：

| 方向 | 消息 | 含义 |
| --- | --- | --- |
| 对端 → 设备 | `{"cmd":"hub","voice":true}` | 对端在这条连接上接收语音。设备回 `{"ack":"hub","ok":true,"chat":true,"cards":true,"threads":true}`；`chat` 表示固件认识[对话](#对话)一节里的 `chat` 和 `helpers`，`cards` 表示它认识 `card` 和 `tasks`，`threads` 表示它把对话和任务分开显示（`tasks` 里可以带做完的事） |
| 设备 → 对端 | `{"cmd":"voice","state":"start","rate":16000,"codec":"ima-adpcm","card":"c12"}` | 一段录音开始。`card` 只在按下时屏幕上有一件事（第二屏上的那张卡、第三屏上选中的那件）时才有：这句话是对它说的。在第三屏按下时后面还有 `"pin":true`：这句话是在那件事里面说的，一定归到它 |
| 设备 → 对端 | 语音帧 | 一条通知一帧，见下文 |
| 设备 → 对端 | `{"cmd":"voice","state":"end","frames":N,"dropped":D,"ms":M}` | 录音完整结束 |
| 设备 → 对端 | `{"cmd":"voice","state":"cancel"}` | 丢弃已经收到的部分 |

语音帧和文本行走同一个 TX 特征，一条通知就是一帧：`0xFF`、一个序号字节、编码这一帧
之前的编码器状态（预测值两字节小端、步长下标一字节），然后是 IMA ADPCM 数据，低 4 位
在前。`0xFF` 不会出现在 UTF-8 里，所以对端看一条通知的第一个字节就能区分语音帧和
文本。音频是 16 kHz 单声道、每个采样 4 位，约 8 KB/s。每帧自带解码状态，丢一帧只损失
这一帧的 30 毫秒。

没有连接时，或者连着一个没有声明语音的对端（Claude 桌面端）时按住 `确认`，设备只
显示一行说明，不会录音。音频芯片在第一次使用时初始化，每段录音结束后休眠。

## 对话

用 `hub` 介绍过自己的对端，会再用下面几条消息报告和小幽的对话。它们属于同一个扩展，
所以 Claude 桌面端永远不会发；旧固件会回一条错误应答，对端忽略即可。对端看到应答里
有 `cards` 才发 `card` 和 `tasks`。

| 方向 | 消息 | 含义 |
| --- | --- | --- |
| 对端 → 设备 | `{"cmd":"chat","phase":P,"said":"…","reply":"…","agent":"…","stage":"…","mood":M,"card":"c12","doing":N}` | 小幽此刻在干什么：**第一屏**显示的就是它。只有 `phase` 是必需的 |
| 对端 → 设备 | `{"cmd":"card","id":"c12","at":"14:02","state":S,"agent":"…","edits":N,"said":"…","reply":"…"}` | 新增或更新一件事的卡：**第二屏**。`id` 和 `state` 是必需的 |
| 对端 → 设备 | `{"cmd":"card","clear":true}` | 忘掉所有的卡（对端马上要重新发一遍） |
| 对端 → 设备 | `{"cmd":"tasks","list":[{"id":"c12","agent":"…","title":"…","state":T,"secs":42,"p1":"…","p2":"…"}]}` | 交给帮手的事：**第三屏**。`T` 是 `working`、`waiting`、`queued`，做完的是 `done`、`failed`、`cancelled`（对端只发给声明了 `threads` 的固件；这时 `p1` 是结论，而这件事的 `card` 里 `reply` 是它最近的来回，“你：”“小幽：”各一段，最多 480 字节）。最多保留四件；空列表表示一件都没有 |
| 对端 → 设备 | `{"cmd":"helpers","list":[{"name":"…","about":"…"}]}` | 小幽可以把活儿交给哪些 agent；最多保留四个。空列表表示清空 |

`chat`：`phase` 取 `idle`（现在没有在说的话）、`thinking`、`helper`（她把活交给了
`agent` 里的那个 agent；`stage` 是这件事的标题）、`done`（`reply` 里是她的简报，
一两句）或 `failed`（`reply` 里是原因）。`mood` 取 `idle`、`busy`、`ask`、`happy` 或
`oops`，决定这一轮结束时宠物的表情。`said` 是主人说的话，录音转成文字之前为空。
`card` 是这句话归到了哪张卡；`doing` 是后台还在做的事的件数。

`card`：`state` 取 `working`（帮手在做）、`waiting`（等你点头）、`done`、`failed`、
`cancelled` 或 `talking`。`agent` 是谁在做或做的，空表示小幽自己答的。`said` 是这件事
的第一句话，`reply` 是小幽最新的话，`edits` 是补充或改过几次，`at` 是开始的时间
（“时:分”）。同一个 `id` 再来一次是原位更新，卡的先后不变。

`tasks`：`state` 取 `working`、`waiting` 或 `queued`。`secs` 是已经做了多少秒，设备自己
接着数。`p1`、`p2` 是最近两步：`p1` 在前，`p2` 是最新的；只有一步时放在 `p1`。

长度上限：`said` 和 `stage` 159 字节，`agent` 和帮手的 `name` 23 字节，`about` 63 字节，
`reply` 959 字节，任务的 `title` 47 字节，`p1`、`p2` 各 63 字节；更长的文字会在字符
边界处截断。`reply` 达到 956 字节时已经放不下下一个字，当作对端截过，同样标注已截断。
卡的 `id` 最多 11 字节，更长的不收（截断了就成了另一张卡）。这些消息不
逐条应答；解析不了的那条会得到 `{"ack":"…","ok":false,…}`，并且不改变任何状态。

授权弹窗不用新消息：对端把要确认的操作放进心跳的 `prompt`（`tool` 是“帮手 · 工具”，
`hint` 是内容原文，最多显示 319 字节），设备的回答走原有的 `permission` 命令。

### 设备上留着什么

卡留在设备内存里，按开卡的先后：最多 12 张、4096 字节文字。新的放不下时，丢掉最旧的。
每张卡只有“第一句话”和“小幽最新的话”两段，中间的补充只显示改过几次；完整的来回在
手机上看。

连接断开不会清掉卡：小幽睡着了，说过的话照样可以读；第一屏上的那一轮和第三屏的任务
单子会清空，因为没有人在报告它们了。重新连上后，对端先发 `card clear`，再把最近的
几张卡发一遍。

还没有卡的那一轮（录音正在听写、她还在想）和不会有卡的那一轮（录音没听清），第二屏
直接显示这一轮本身。从不发 `card` 的对端（Claude 桌面端、旧版手机 App）也一样：第二屏
只有最新的那条回复。

发送 `chat` 的中枢在心跳里把 `msg` 留空，也不发 `turn` 事件。一条连接上只要中枢
发过 `chat`，固件就忽略它的 `turn` 事件，并且把心跳里的数字只当作通知，不当作小幽
在忙。从不发 `chat` 的中枢按桌面端的方式显示：数字不为零时显示在忙，回复取自 `turn`。

录音刚发出去、还在等听写结果时，对端报告别的事结束了（后台的一件事做完，或者上一轮），
设备只收下“在做几件”，不把正在等的这一轮换掉。

## 经蓝牙换固件

改一下屏幕上的东西不用再插线：手机伴侣把新的应用镜像经现有的加密蓝牙连接传给设备。
闪存里有两个一样大的应用槽位（各 3.9 MB，见
[固件布局](development/engineering/firmware-layout.zh_CN.md)）。正在运行的那个照常工作，
新镜像写进另一个；核对通过后设备重启进新的。新固件第一次启动时处于“待认可”状态：
手机连上来说一声 `confirm` 才算数；三分钟内没等到，或者中途又重启了，就退回上一版。
所以一版启动不了、或者连不上蓝牙的固件不会把设备变成只能插线救的砖。

这也是中枢扩展的一部分：Claude 桌面端不会发这些，旧固件会回一条错误应答。设备的回话
都是一层的 JSON 对象。

| 方向 | 消息 | 含义 |
| --- | --- | --- |
| 对端 → 设备 | `{"cmd":"fw","op":"info"}` | 现在是哪一版。设备回 `{"ack":"fw","ok":true,"op":"info","build":B,"ver":V,"state":"valid"\|"pending","slot":S,"prev":P,"max":N}`：`build` 是固件 ELF 的 SHA-256 前 16 位，`prev` 是另一个槽位里那一版的 `build`（没有就是空串），`max` 是一个槽位放得下多大的镜像 |
| 对端 → 设备 | `{"cmd":"fw","op":"begin","size":N,"sha256":"…"}` | 要传一份 N 字节的镜像。设备回 `{"ack":"fw","ok":true,"op":"begin","offset":K,"chunk":C,"window":W}`：从偏移 K 开始发（接着上次断掉的地方时不是 0），一帧最多带 C 字节数据，发出去的不能超过“已写进闪存的 + W” |
| 对端 → 设备 | 数据帧 | 一次写入一帧，见下文 |
| 设备 → 对端 | `{"evt":"fw","got":G,"done":D}` | 每写进闪存 1 KB 报一次，没有进展时每秒一次。`got` 是下一个要的偏移，`done` 是已写进闪存的字节数。带 `"rewind":true` 时表示中间缺了，请从 `got` 重新发 |
| 对端 → 设备 | `{"cmd":"fw","op":"end"}` | 发完了。设备核对 SHA-256 和镜像本身，通过就回 `{"ack":"fw","ok":true,"op":"end"}`，约一秒后重启。还没收全时回 `"ok":false,"error":"incomplete","got":G`，从 G 接着发即可 |
| 对端 → 设备 | `{"cmd":"fw","op":"confirm"}` | 认可正在运行的新固件 |
| 对端 → 设备 | `{"cmd":"fw","op":"rollback"}` | 切回另一个槽位里的那一版并重启，不用重新传 |
| 对端 → 设备 | `{"cmd":"fw","op":"abort"}` | 放弃这一次；写了一半的作废，正在运行的固件不受影响 |

数据帧和文本行走同一个 RX 特征，一次写入就是一帧：`0xFE`、四字节小端的偏移，然后是
镜像数据。`0xFE` 不会出现在 UTF-8 里，所以设备看一次写入的第一个字节就能把它和文本
分开，和语音帧用 `0xFF` 是同一个办法、方向相反。帧用“不等应答”的写入发，文本行可以
穿插在帧之间，所以传输期间心跳照常。每帧自带偏移：重复的直接丢掉，缺了就报
`rewind`。连接断了不算失败：设备把收了一半的留五分钟，重新连上后用同样的 `size` 和
`sha256` 再发一次 `begin`，它会说从哪儿接着发。

设备拒绝时 `error` 是这几个词之一：`size`（太小或者比槽位大）、`no slot`（分区表里
没有第二个槽位）、`unconfirmed`（正在运行的固件还没被认可，先发 `confirm`）、`link`
（蓝牙一次能带的数据太少）、`memory`、`flash`、`sha256`、`image`（镜像本身核对不过）、
`restarting`、`busy`、`no previous` 和 `previous invalid`（没有可以切回去的上一版）。

传输期间屏幕上是小幽和一条进度；这时按键不起作用，来了要点头的事也不打断，熄着的
屏幕会亮起来。没换成时回到平常的画面，底下那一行说一声。

只有配对并加密的连接才收得到这些消息，所以能换固件的就是配对过的那一台手机（或
电脑）。镜像没有签名：信任链是 Runtime 的令牌 → 手机 → 蓝牙配对。拿到 Runtime 令牌
的人可以让手机把任意镜像推给设备；Runtime 只应该在可信的网络里监听。

**分区表不能经蓝牙改。** 从单槽位的旧固件换到这一版要插线刷一次（见[刷机](#刷机)）；
之后的版本只要不改 `partitions.csv` 就都能经蓝牙换。

每一版固件都留在 Runtime 所在的电脑上，可以随时换回其中任何一版：见
[`runtime/README.zh_CN.md`](../runtime/README.zh_CN.md#设备固件)。

## 保存的数据

设备保存自己的名称、对端发来的主人名字、蓝牙开关、允许和拒绝的次数，以及蓝牙
绑定信息。通知、帮手的名字、请求的说明、请求编号、进行中的一轮和任务单子只在内存里，
连接断开或 30 秒没有收到心跳时清除。卡留在内存里，直到设备重启、对端让清掉或者被
更新的挤掉；它们不会写入闪存。

## 未实现

- 文件夹推送（`char_begin` 等命令）会以错误应答拒绝。
- 没有“始终允许”，设备只发送 `once` 或 `deny`。想永久放行的规则写在各自命令行工具的
  设置里。
- 卡只留在内存里。重启就没了，等手机重新连上再发一遍；更早的在手机上看。
- 一件事不能用按键取消：按住 `确认` 对它说一句“不用了”。
- 引导程序和分区表不能经蓝牙换，只有应用镜像可以。
- 镜像没有签名，也没有压缩或差分：每次传的是完整的应用镜像（约 1.7 MB）。
- 本应用不使用扬声器、Wi-Fi 和低功耗休眠。
- 回复只以文字显示，不会念出来。

## 内存

这块板没有 PSRAM。LVGL 直接从系统堆分配，不单独划固定内存池，所以界面、蓝牙和
任务栈共用同一份余量。固件每分钟输出一行 `heap: free=… min=…`（低于 12 KB 时为
警告），上板验收时请查看。

和长对话那一版相比，静态内存多了大约 3 KB：卡的附加信息（12 张，每张约 50 字节）、
任务单子（4 件，每件约 220 字节，状态里一份、给界面的快照里一份），以及事件结构里的
一份任务单子和一张卡。蓝牙收到的一行现在解析到应用任务那个静态的事件缓冲里，不再在
任务栈上放一个几 KB 的事件结构。堆：第二屏只摆一张卡的两段字，比之前给每一轮都留
一份副本要少。这些都没有在设备上实测过；主机渲染器里 LVGL 的峰值约 69 KB（64 位
主机，对象比固件里大）。

经蓝牙换固件常驻的是一个任务（栈 5 KB）和两个很小的队列；收镜像用的缓冲区
（2.3 KB）在第一次收的时候才申请，之后留着。镜像收全后的核对最吃栈，日志里
`image accepted` 那一行会报这个任务栈的最低余量，上板时请看一眼。

## 构建、测试与预览

```bash
./tools/validate.sh            # host tests, firmware build, merged-image check
python3 tools/gen_pocket_fonts.py   # after editing main/pocket_text.h
cmake -S tools/ui_preview -B /tmp/ui_preview && cmake --build /tmp/ui_preview
/tmp/ui_preview/ui_preview /tmp/ui_preview   # writes one PPM image per screen
```

协议、状态机和编排层的主机测试需要 `IDF_PATH` 里的 cJSON；没有时静态门禁会把它们
报告为跳过。手机伴侣和固件之间的换固件互通测试除了 cJSON 还需要 JDK，缺哪个同样
报告为跳过。

换固件里和硬件有关的那一半（`main/pocket_update.c`：写另一个槽位、核对、切换、等认可、
到时间退回）在主机上测不了，用模拟器测：

```bash
tests/update_emulator/run.sh   # needs ESP-IDF 5.5 and Espressif's QEMU (qemu-system-riscv32)
```

它把这个文件原样编进一个小程序，放到模拟的 ESP32-C3 上，用的是真的 ESP-IDF 引导程序和
产品的分区表。测试程序扮演手机，依次检查：该拒绝的请求被拒绝；哈希对不上的镜像收全了
也不切换；传输中丢帧、重复、乱序、断线后续传，最后核对通过并重启进新槽位；新固件没被
认可就退回上一版；认可之后保持不变；切回另一个槽位里的那一版。它不在
`tools/validate.sh` 里，因为需要另外安装模拟器。模拟器里没有蓝牙，所以蓝牙这一段、
真实的传输速度和内存余量仍然只能上板看。模拟器自己偶尔会卡住（闪存操作期间丢掉定时器
中断），脚本发现后会在同一份闪存上重新启动它，对固件来说相当于断了一次电。

## 刷机

每次推送到功能分支且改动了固件，GitHub Actions 都会构建一次，并把合并镜像挂到名为
*Claude Pocket firmware build N* 的预发布版本上。设备开机，用能传数据的 USB 线接到
电脑之后：

```bash
./tools/flash_pocket.sh              # downloads the newest build and writes it
./tools/flash_pocket.sh image.bin    # writes a merged image you already have
```

脚本会自己找串口（一个都没有，或者有不止一个而没有用 `--port` 指定时会停下），第一次
使用时把 `esptool` 装进一个独立的 Python 环境，列出镜像、它的 SHA-256 和串口，写入前
先问一句。不是合并镜像的文件它不会写。

合并镜像写在 `0x0`，会重置设置区：设备会忘掉自己的名称和蓝牙配对。在手机上删掉原来
的配对，再重新配对。想保留设置的做法见
[烧录与已存数据](development/engineering/firmware-layout.zh_CN.md#烧录与已存数据)。

设备上一旦是带[经蓝牙换固件](#经蓝牙换固件)的版本，之后就不用再插线：新版本由手机
伴侣传过去，设置和配对都保留。插线只在三种情况下还需要：设备上是更早的单槽位固件、
改了分区表、或者蓝牙这条路本身被改坏了而且两个槽位里的都不能用。插线刷过之后，在
Runtime 那台电脑上运行 `python3 -m xiaoyou_runtime firmware fetch` 把同一版入库，
以后才能换回它。

## 上板验收

构建通过和主机预览都不等于设备验证。这一版（三屏）还没有在硬件上跑过。需要检查：

1. 开机显示小幽在睡觉；顶栏显示连接状态的圆点、三个小点和电量。
2. 配对：出现配对码页面，配对码被接受；任意一方重启后无需配对码即可重连。
3. `确认` 短按在三屏之间轮着切，顶栏的小点跟着走；双击打开菜单，在菜单里双击回到
   第一屏。短按切屏的那一点延迟能不能接受。
4. 按住 `确认`、说话、松开：说话时音量条在动；第一屏先显示在听写，再显示在想和你说的
   话，最后是简报或“交给帮手了”。
5. 第二屏：刚说的话先显示为“新的一件”，卡来了之后换成那张卡。长回答从开头显示，
   `下` 一次翻七行，上下沿不出现半行；翻到头再按换到下一件，`上` 同理。
6. 小幽把活儿交出去时，信在动，帮手的名字是它的颜色，计时在走；顶栏出现“在做 N”。
7. 第三屏：几件事同时在做时都列出来，计时各自在走；`上`、`下` 换选中项，下面的两步
   跟着换；做完的事留在单子上，选中它时下面是结论。第二屏不跟着第三屏的选择走，
   上下翻时也看不到交给帮手的事。在第三屏选中一件做完的事按住说话，这句话接在那件事上。
8. 在第二屏、第三屏按住 `确认` 说“改成……”或“不用了”：那件事被改或被取消，而不是
   新开一件。
9. agent 要做需要确认的操作时弹窗出现并点亮屏幕；`确认` 可以、`下` 不行、`上` 翻看长
   说明；对端反映每次决定。连按两下 `确认` 只算一次。
10. 每个页面、每种状态都没有方框、裁切或重叠，包括较长的中英文混排。
11. 取消配对和恢复出厂设置会先要求确认，行为与上文一致。
12. 断开连接后 30 秒内小幽睡着；卡照样可以读，重连之后不会多出重复的卡。
13. 屏幕上有十来张卡、四件事在做时，以及录音期间，`heap:` 日志里的最小值仍有充足
    余量；长时间运行时可用堆保持稳定；蓝牙距离和续航需要实测，不能假定。
14. 经蓝牙换固件：在 Runtime 上指定一版后，设备显示进度，传完自己重启，重连后手机
    伴侣显示“新固件装好了”，名称和配对都还在；记下整个过程用了多久。传到一半把手机
    拿远再拿回来，能接着传。
15. 换回上一版：指定设备另一个槽位里的那一版，设备几秒内重启回去，不重新传。
16. 自动退回：推一版新固件后，在它重启时关掉手机蓝牙三分钟以上，设备应该自己回到
    上一版；再打开蓝牙，手机伴侣报告没装成。
17. 换固件期间和之后，`heap:` 日志的最小值和 `image accepted` 那一行里的任务栈余量
    都还有富余。
