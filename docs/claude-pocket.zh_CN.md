# Claude Pocket

Claude Pocket 把 FoloToy AI Passport 变成小幽随身的那张脸。小幽是一只小幽灵，
也是你唯一要对话的对象。设备通过加密的低功耗蓝牙连着手机伴侣：按住按键说话，
她的回答出现在屏幕上；她把活儿交给别的 agent 时，屏幕上能看到她在找谁。

这条连接使用 Anthropic 在
[`anthropics/claude-desktop-buddy`](https://github.com/anthropics/claude-desktop-buddy)
公开的 *Hardware Buddy* 蓝牙协议，并为手机伴侣加了一小段扩展。不用扩展时，同一份
固件仍然可以作为 Claude 桌面端的伴侣使用（开启了开发者模式的 macOS 和 Windows；
Anthropic 把这个蓝牙桥定位为面向创客的功能，不是正式支持的产品功能）。

## 功能

| 能力 | 行为 |
| --- | --- |
| 对话 | 首页就是对话：顶上一条是小幽和她此刻在干什么，下面是一轮接一轮的对话，你说的和她说的。她的心情就是宠物的表情 |
| 把活儿交出去 | 别的 agent 替她干活时，顶上那一条里有一封信从小幽飞向那个 agent 的名牌，旁边在计时。每个 agent 有自己的颜色 |
| 往回看 | `上`、`下` 在对话里滚动，一次八行。一个回答最多 959 字节，约 320 个汉字 |
| 之前的对话 | 30 分钟没有新的一轮，对话就收起来，首页回到休息的样子。双击 `上` 把它接回来 |
| 按住说话 | 按住 `确认` 录音，音频经蓝牙发给手机伴侣，见[按住说话](#按住说话) |
| 审批 | 由小幽发问；谁要做什么原样显示；在设备上点头或摇头 |
| 通知 | 对端发来的最近四条记录，在菜单里。有没看的通知时，空闲的首页会写出有几条 |
| 帮手 | 小幽可以把活儿交给哪些 agent（由对端告知），在菜单里 |
| 配对 | LE Secure Connections，设备显示六位配对码 |

颜色只回答一个问题：现在是谁在干活。小幽是淡紫色；每个帮手有自己的颜色，同一个
名字的颜色固定不变。绿、红、黄只表示可以、不行和“看一下这个”，不作他用。

连的是 Claude 桌面端而不是手机伴侣时，首页显示桌面端报告的内容：干活时的状态行，
以及最新的回复。这种模式下不能说话，因为桌面端的协议里没有提问和语音这类消息。

## 配对

连手机伴侣（通常的用法）：打开“小幽中枢”App，开始连接，在手机的蓝牙提示框里
输入设备显示的六位数字。见 [`companion/README.zh_CN.md`](../companion/README.zh_CN.md)。

连 Claude 桌面端：

1. 选择 **Help → Troubleshooting → Enable Developer Mode**。
2. 选择 **Developer → Open Hardware Buddy…**，点击 **Connect**。
3. 选择名为 `Claude-XXXXXX` 的设备；睡着的首页和“连接指引”页显示同一个名称。
4. 在操作系统的蓝牙提示框中输入设备显示的六位数字。

绑定之后设备会自动重连。如果列表里找不到设备，请确认设备菜单里的蓝牙是打开的。

## 按键

三个按键分别是 `上`、`下`、`确认`。屏幕最下面一行始终写着此刻各个键是干什么的。

| 所在界面 | `上` / `下` 短按 | `确认` 短按 | `确认` 按住 | `上` 长按 |
| --- | --- | --- | --- | --- |
| 首页 | 对话滚动八行 | 回到最新一轮 | 说话，松开发送 | 打开菜单 |
| 菜单、更多设置 | 移动选中项（循环） | 执行选中项 | 回到首页 | 回到首页 |
| 通知、帮手 | — | 返回菜单 | 回到首页 | 回到首页 |
| 连接指引 | 滚动三行 | 返回更多设置 | 回到首页 | 回到首页 |
| 等你点头或摇头的请求 | `上` 翻看说明；`下` 不行 | 可以 | — | — |
| 取消配对 / 恢复出厂的确认 | `下` 取消 | 确定 | — | — |
| 熄屏 | 任意短按只点亮屏幕，不做其他事 | | 点亮屏幕并开始说话 | 点亮屏幕 |

请求、配对码和二次确认会占据整个屏幕，熄屏时会自动亮屏；你刚问的话有了回答时
也一样。按键只对按下那一刻屏幕上显示的内容生效；如果按键和新请求同时到达，这次
按键会被丢弃，不会套用到新请求上。每个请求只接受一次决定，发送失败会显示为失败，
不会当作已允许。

小幽只负责“问”。谁在请求、要做什么直接来自对端，不会被转述；气泡里放不下的
名称会在说明卡片的开头完整再写一遍。

快速连按两下按一次短按处理，只有一个例外：在首页，之前的对话被收起来的时候，双击
`上` 把它们接回来，并停在其中最后一轮上。有东西可以接回来时，按键提示里会写。

菜单里有通知、帮手、屏幕亮度（五档）、蓝牙开关、熄灭屏幕和更多设置；更多设置里
是连接指引、取消配对和恢复出厂设置。亮度在重启后回到最大。

设备自己有话要说时（录音太短、连接还没准备好、蓝牙开关失败），这句话会代替按键
提示显示六秒。

## 文字与字库

所有固定界面文案都是简体中文，集中在
[`main/pocket_text.h`](../main/pocket_text.h)。字库由
[`tools/gen_pocket_fonts.py`](../tools/gen_pocket_fonts.py) 从思源黑体
（Noto Sans SC）生成，见[素材文档](../assets/README.zh_CN.md#字库fonts)。

对端发来的文字（你说的话、小幽的话、帮手的名字、通知、谁在请求以及要做什么）
使用覆盖可打印 ASCII、GB2312 全部 6763 个汉字和常用标点的字库。超出这个范围的
字符（表情符号、仅繁体使用的字、其他文字）会显示为占位方框，不会被丢掉或替换。
超出显示区域的文字以省略号结尾；说明超过 319 字节、回答超过 959 字节时会标注
已截断。LVGL 不处理中文的行首行尾禁则，所以折行后一行可能以标点开头。

## 按住说话

在首页按住 `确认`。小幽先说稍等，随后说她在听：音量条会跟着你的声音动，
这就表示麦克风已经在收音。说完松开就发送。之后首页显示录音正在路上，直到对端
告诉它听到了什么。按下不到约三分之一秒就松开，不会发送任何内容。一段录音到 30 秒
会自动停止并照常发送。

设备只负责录音和传输。把语音变成文字、给出回答都由对端完成：手机伴侣把录音转给
小幽 Runtime（见 [`companion/README.zh_CN.md`](../companion/README.zh_CN.md) 和
[`runtime/README.zh_CN.md`](../runtime/README.zh_CN.md)）。

语音是在桌面端协议之上的扩展，对端没有声明之前是关闭的，所以 Claude 桌面端永远
不会收到它不认识的数据：

| 方向 | 消息 | 含义 |
| --- | --- | --- |
| 对端 → 设备 | `{"cmd":"hub","voice":true}` | 对端在这条连接上接收语音。设备回 `{"ack":"hub","ok":true,"chat":true}`；`chat` 表示固件认识[对话](#对话)一节里的消息 |
| 设备 → 对端 | `{"cmd":"voice","state":"start","rate":16000,"codec":"ima-adpcm"}` | 一段录音开始 |
| 设备 → 对端 | 语音帧 | 一条通知一帧，见下文 |
| 设备 → 对端 | `{"cmd":"voice","state":"end","frames":N,"dropped":D,"ms":M}` | 录音完整结束 |
| 设备 → 对端 | `{"cmd":"voice","state":"cancel"}` | 丢弃已经收到的部分 |

语音帧和文本行走同一个 TX 特征，一条通知就是一帧：`0xFF`、一个序号字节、编码这一帧
之前的编码器状态（预测值两字节小端、步长下标一字节），然后是 IMA ADPCM 数据，低 4 位
在前。`0xFF` 不会出现在 UTF-8 里，所以对端看一条通知的第一个字节就能区分语音帧和
文本。音频是 16 kHz 单声道、每个采样 4 位，约 8 KB/s。每帧自带解码状态，丢一帧只损失
这一帧的 30 毫秒。

没有连接时，或者连着一个没有声明语音的对端（Claude 桌面端）时按住 `确认`，设备只
显示一行说明，不会录音。音频芯片在第一次使用时初始化，每段录音结束后休眠。

## 对话

用 `hub` 介绍过自己的对端，会再用两条消息报告和小幽的对话。它们属于同一个扩展，
所以 Claude 桌面端永远不会发；旧固件会回一条错误应答，对端忽略即可。

| 方向 | 消息 | 含义 |
| --- | --- | --- |
| 对端 → 设备 | `{"cmd":"chat","phase":P,"said":"…","reply":"…","agent":"…","stage":"…","mood":M}` | 当前这一轮进行到哪了。只有 `phase` 是必需的 |
| 对端 → 设备 | `{"cmd":"helpers","list":[{"name":"…","about":"…"}]}` | 小幽可以把活儿交给哪些 agent；最多保留四个。空列表表示清空 |

`phase` 取 `idle`（还没说过话）、`thinking`、`helper`（`agent` 里的那个 agent 正在
替她干活；`stage` 是她交代时说的话）、`done`（她的回答在 `reply` 里）或 `failed`
（`reply` 里是原因）。`mood` 取 `idle`、`busy`、`ask`、`happy` 或 `oops`，决定这一轮
结束时宠物的表情。`said` 是主人说的话，录音转成文字之前为空。长度上限：`said` 和
`stage` 159 字节，`agent` 和帮手的 `name` 23 字节，`about` 63 字节，`reply` 959 字节；
更长的文字会在字符边界处截断。这两条消息不逐条应答；解析不了的那条会得到
`{"ack":"chat","ok":false,…}`，并且不改变任何状态。

### 设备上留着什么

对端只报告当前这一轮。已经结束的各轮由设备自己留在内存里，旧的在前：最多 12 轮、
4096 字节文字，大约是十来轮短对话，或者三四个写满的回答。新的一轮放不下时，丢掉
最旧的。一轮在下一轮开始时、连接断开时、或者 30 秒没有心跳时被留下来；那时还在
进行中的一轮不留，因为对端回来后会再报告它。

首页上的各轮是一段对话。30 分钟没有新的一轮、也没有在首页按过键
（`BUDDY_SESSION_IDLE_MS`），或者中枢在有过对话之后报告 `idle`（手机 App 重启后
会这样），这一段就结束并被收起来。这只影响显示：不会向对端发送任何东西，Runtime
自己的上下文不受影响。中枢每 30 秒、以及重连之后会重发最后一条 `chat`；设备已经
留下的那一轮按文字认出来，不会显示两遍。

连接断开不会清空页面：顶上那一条显示小幽睡着了，说过的话照样可以读。

发送 `chat` 的中枢在心跳里把 `msg` 留空，也不发 `turn` 事件。一条连接上只要中枢
发过 `chat`，固件就忽略它的 `turn` 事件，并且把心跳里的数字只当作通知，不当作小幽
在忙。从不发 `chat` 的中枢（旧版手机 App）按桌面端的方式显示：数字不为零时显示在忙，
回复取自 `turn`。

## 保存的数据

设备保存自己的名称、对端发来的主人名字、蓝牙开关、允许和拒绝的次数，以及蓝牙
绑定信息。通知、帮手的名字、请求的说明、请求编号和进行中的一轮只在内存里，连接
断开或 30 秒没有收到心跳时清除。对话里已经结束的各轮留在内存里，直到设备重启或
被更新的挤掉；它们不会写入闪存。

## 未实现

- 文件夹推送（`char_begin` 等命令）会以错误应答拒绝。
- 没有“始终允许”，设备只发送 `once` 或 `deny`。
- 之前的各轮只留在内存里。重启就没了，设备也不会向手机要；完整的历史在手机上。
- 进行中的一轮不能在设备上取消。
- 本应用不使用扬声器、Wi-Fi 和低功耗休眠。
- 回复只以文字显示，不会念出来。

## 内存

这块板没有 PSRAM。LVGL 直接从系统堆分配，不单独划固定内存池，所以界面、蓝牙和
任务栈共用同一份余量。固件每分钟输出一行 `heap: free=… min=…`（低于 12 KB 时为
警告），上板验收时请查看。

对话要用到之前的界面不需要的内存。静态内存：回答的缓冲区在三处从 420 字节加大到
960 字节，另外还要保存说过的话、正在帮忙的帮手和帮手列表，之前各轮的历史再占
4.2 KB，合计约 8 KB。堆：首页为显示出来的每一轮保留一份文字副本，最多是 4 KB 历史
加上当前这一轮，每轮还有两个 LVGL 标签，第一次用到时创建；对话收起来时这些副本
会释放。这些还没有在设备上实测。

共用任何页面。

## 上板验收

构建通过和主机预览都不等于设备验证。需要在硬件上检查：

1. 开机显示小幽在睡觉；顶栏显示连接状态的圆点和电量。
2. 配对：出现配对码页面，配对码被接受；任意一方重启后无需配对码即可重连。
3. 按住 `确认`、说话、松开：说话时音量条在动；首页先显示录音在路上，再显示听到的
   话，最后是回答。长回答从开头显示，每次滚动八行，上下沿不出现半行。
4. 小幽把活儿交出去时，信在动，帮手的名字是它的颜色，计时在走。失败的一轮会显示
   原因。
5. 聊了几轮之后，`上` 能一直往回翻到第一轮，`确认` 回到最新一轮。往回翻着的时候
   来了新的一轮，页面会回到那一轮。30 分钟没有新的一轮后首页回到休息的样子；双击
   `上` 把对话接回来，单击不会。
6. 每个页面、每种状态都没有方框、裁切或重叠，包括较长的中英文混排。
7. 请求占据屏幕；`确认` 可以、`下` 不行、`上` 翻看长说明；对端反映每次决定。
8. 熄屏时收到请求或回答会自动亮屏。
9. 取消配对和恢复出厂设置会先要求确认，行为与上文一致。
10. 断开连接后 30 秒内小幽睡着；对话照样可以读，重连之后最后一轮不会显示两遍。
11. 屏幕上有十来轮对话时、以及录音期间，`heap:` 日志里的最小值仍有充足余量；长时间
    运行时可用堆保持稳定；蓝牙距离和续航需要实测，不能假定。

## 后续计划

1. **把回复念出来。** 现在回复只有文字。要从设备的扬声器播放，需要一条下行音频
   通道，以及对端的语音合成。
2. **更省的编码。** ADPCM 需要约 8 KB/s 的蓝牙吞吐。Opus 只要四分之一，但在没有
   PSRAM 的板子上要多占内存和算力；只有上板测试出现丢帧时才值得做。
3. **出门在外。** 手机目前只能在局域网里连到 Runtime。
