# Claude Pocket

Claude Pocket 把 FoloToy AI Passport 变成 Claude 桌面端的随身伴侣：通过加密的
低功耗蓝牙连接电脑，显示 Claude 正在做什么，并且可以用一个按键允许或拒绝权限请求。

它使用 Anthropic 在
[`anthropics/claude-desktop-buddy`](https://github.com/anthropics/claude-desktop-buddy)
公开的 *Hardware Buddy* 蓝牙协议。这个蓝牙桥只存在于开启了开发者模式的 macOS 和
Windows 版 Claude 桌面端；Anthropic 把它定位为面向创客的功能，不是正式支持的产品
功能。Claude 手机 App 没有这个接口，所以设备只能在运行 Claude 的那台电脑的蓝牙
范围内工作。

## 功能

| 能力 | 行为 |
| --- | --- |
| 状态 | 待命、工作中、等待确认、连接状态、会话数量 |
| 最新回复 | Claude 最近一轮回复的开头文字（前 419 字节） |
| 最近动态 | 桌面端发来的最近四条记录 |
| 用量 | 今日和本次启动以来的输出 token、允许次数、拒绝次数、运行时长、电池 |
| 审批 | 由小幽发问；工具名和参数说明原样显示；在设备上允许一次或拒绝 |
| 配对 | LE Secure Connections，设备显示六位配对码 |

界面围绕一只像素宠物“小幽”（一只小幽灵）展开。首页用它的表情表示状态：没连上
时睡觉、待命、干活、有事找你、允许之后开心、发送失败时沮丧。权限请求、配对和
危险操作的确认，都是小幽在气泡里跟你说话，你按下的键会变成你的回答。

设备不能向 Claude 发送提问或语音：协议里没有这类消息。见[后续计划](#后续计划)。

## 与 Claude 桌面端配对

1. 在 Claude 桌面端选择 **Help → Troubleshooting → Enable Developer Mode**。
2. 选择 **Developer → Open Hardware Buddy…**，点击 **Connect**。
3. 选择名为 `Claude-XXXXXX` 的设备；设备首页和“连接指引”页显示同一个名称。
4. 在操作系统的蓝牙提示框中输入设备显示的六位数字。

绑定之后设备会自动重连。如果列表里找不到设备，请确认设备设置里的蓝牙是打开的。

## 按键

三个按键分别是 `上`、`下`、`确认`。

| 所在界面 | `上` / `下` | `确认` 短按 | `确认` 长按 |
| --- | --- | --- | --- |
| 首页、最新回复、最近动态、用量 | 上一页 / 下一页（循环） | 回到首页 | 打开设置 |
| 设置 | 移动选中项（循环） | 执行选中项 | 回到首页 |
| 连接指引 | 滚动三行 | 返回设置 | 回到首页 |
| 权限请求 | `上` 翻看说明；`下` 拒绝 | 允许一次 | — |
| 取消配对 / 恢复出厂的确认 | `下` 取消 | 确定 | — |
| 熄屏 | 任意短按只点亮屏幕，不做其他事 | | |

权限请求、配对码和二次确认会占据整个屏幕，熄屏时会自动亮屏。按键只对按下那一刻
屏幕上显示的请求生效；如果按键和新请求同时到达，这次按键会被丢弃，不会套用到新
请求上。每个请求只接受一次决定，发送失败会显示为失败，不会当作已允许。

小幽只负责“问”。工具名和参数说明直接来自桌面端，不会被转述；气泡里放不下的
工具名会在说明卡片的开头完整再写一遍。

快速连按两下按一次短按处理。

设置里有屏幕亮度（五档）、蓝牙开关、连接指引、熄灭屏幕、取消配对和恢复出厂设置。
亮度在重启后回到最大。

## 文字与字库

所有固定界面文案都是简体中文，集中在
[`main/pocket_text.h`](../main/pocket_text.h)。字库由
[`tools/gen_pocket_fonts.py`](../tools/gen_pocket_fonts.py) 从思源黑体
（Noto Sans SC）生成，见[素材文档](../assets/README.zh_CN.md#字库fonts)。

电脑发来的文字（状态行、动态、回复、工具名、参数说明）使用覆盖可打印 ASCII、
GB2312 全部 6763 个汉字和常用标点的字库。超出这个范围的字符（表情符号、仅繁体
使用的字、其他文字）会显示为占位方框，不会被丢掉或替换。超出显示区域的文字以
省略号结尾；桌面端发来的参数说明超过 319 字节时会标注“已截断”。LVGL 不处理中文
的行首行尾禁则，所以折行后一行可能以标点开头。

## 保存的数据

设备保存自己的名称、桌面端发来的主人名字、蓝牙开关、允许和拒绝的次数，以及蓝牙
绑定信息。回复、动态、参数说明和请求编号只在内存里，连接断开或 30 秒没有收到
心跳时清除。

## 未实现

- 文件夹推送（`char_begin` 等命令）会以错误应答拒绝。
- 没有“始终允许”，设备只发送 `once` 或 `deny`。
- 本应用不使用扬声器、麦克风、Wi-Fi 和低功耗休眠。

## 内存

这块板没有 PSRAM。LVGL 直接从系统堆分配，不单独划固定内存池，所以界面、蓝牙和
任务栈共用同一份余量。固件每分钟输出一行 `heap: free=… min=…`（低于 12 KB 时为
警告），上板验收时请查看。

## 代码结构

| 路径 | 作用 |
| --- | --- |
| `main/main.c` | 队列、应用任务、蓝牙与设置的衔接 |
| `main/buddy_ble*.c` | NimBLE 外设：Nordic UART Service、安全与绑定 |
| `main/buddy_line.c`、`main/buddy_protocol.c` | 按行组包、有界的 JSON 解析与序列化 |
| `main/buddy_state.c` | 连接、审批和导航的状态机 |
| `main/buddy_orchestrator.c`、`main/buddy_app_logic.c`、`main/buddy_settings.c` | 命令处理、队列策略、NVS 设置 |
| `main/pocket_view.c` | 纯逻辑：视图选择、小幽的表情、数字和时间格式化 |
| `main/pocket_pet.c` | 小幽的 20 × 20 像素造型和各种表情（不依赖 LVGL） |
| `main/pocket_ui.c` | LVGL 界面 |
| `tools/ui_preview/` | 主机端渲染器：用真实的 LVGL 和字库画出每个界面 |

蓝牙、协议和状态层改编自 `demo/claude-buddy-port` 分支；导航重新设计，并新增了
回复内容的解析。界面是全新的，与该分支和基线硬件测试菜单没有共用任何页面。

## 构建、测试与预览

```bash
./tools/validate.sh            # host tests, firmware build, merged-image check
python3 tools/gen_pocket_fonts.py   # after editing main/pocket_text.h
cmake -S tools/ui_preview -B /tmp/ui_preview && cmake --build /tmp/ui_preview
/tmp/ui_preview/ui_preview /tmp/ui_preview   # writes one PPM image per screen
```

协议、状态机和编排层的主机测试需要 `IDF_PATH` 里的 cJSON；没有时静态门禁会把它们
报告为跳过。

## 上板验收

构建通过和主机预览都不等于设备验证。需要在硬件上检查：

1. 开机显示首页；顶栏显示连接状态和电量。
2. 配对：出现配对码页面，配对码被接受；任意一方重启后无需配对码即可重连。
3. 每个页面、每种状态都没有方框、裁切或重叠，包括较长的中英文混排。
4. 权限请求占据屏幕；`确认` 允许、`下` 拒绝、`上` 翻看长说明；桌面端反映每次决定。
5. 熄屏时收到请求会自动亮屏。
6. 取消配对和恢复出厂设置会先要求确认，行为与上文一致。
7. 断开连接（走出范围、退出桌面端）后 30 秒内回到等待状态，并清空回复和动态页。
8. 连上 Claude 并显示权限请求时，`heap:` 日志里的最小值仍有充足余量；长时间运行时
   可用堆保持稳定；蓝牙距离和续航需要实测，不能假定。

## 后续计划

1. **语音通路。** 板上有麦克风，但 ESP32-C3 没有经典蓝牙和 LE Audio，不能当作
   耳麦，桌面端协议也不传音频。语音输入需要另一条通道把语音转成文字再交给
   Claude，这是下一步要设计的内容。
2. **手机伴侣。** 离开电脑仍保持连接需要一个手机 App，因为 Claude 手机 App 不提供
   这个蓝牙桥。
