# 图片消息

## 原状与改动

原固件的 `chat` 和 `card` 只有文字；二进制接收通道专供 OTA 固件。
Pocket Hub 已能下载、打开任务产物里的图片，但输入框和 `/v1/messages`
只收文字或录音，登记产物附件不等于支持主人上传图片。

本次增加鉴权上传、主人图片附件持久化、Codex 原生图片输入、手机选图预览，
以及可协商的蓝牙缩略图能力。文字、语音、审批、配对、固件更新、分区和任务路由
都需要继续回归验证，不能因增加了图片就默认它们通过。

## 交互与边界

- App 0.27.1 起，主对话输入框内的“照片”入口打开系统相册选择器
  （Android 13 及以上；旧系统退回文件选择器）。选图后先显示靠左的小幅本地预览，
  不再等上传成功、再下载缩略图。上传时可以继续输入，准备好后发送。
  上传中按发送会等这批图都传好再自动发出。“照片”用于继续添加，每张预览右上角单独移除；取消选择器保留现有草稿。
  手机一次可选多张、每条消息最多四张（与 Runtime 协议上限一致）；每张选好就开始上传，上传的原图同时写入手机缓存，发出后气泡直接显示、不再从电脑下载。
- 上传区分本地准备、字节写入进度、等待电脑确认、就绪和失败。
  失败保留所选 URI 和文字，可明确点击重试；未完成的图片不会悄悄变成纯文字发送。
  每张图从开始传输起算 45 秒超时。移除、更换、切换来源和页面销毁会作废旧回调并取消连接。
  页面重建后恢复已就绪附件；未完成的选择在来源仍授予读取权限时可重试。
- 超过 1 MiB 且长边超过 2,560 像素的 JPEG 照片，按比例缩至长边 2,560，
  以 JPEG 质量 90 编码，仅在结果更小时使用。先正确应用 EXIF 旋转和镜像。
  PNG、GIF、WebP、较小 JPEG 以及 PNG 截图上传原始字节。
  这能减少符合条件的照片体积；手机网络的实际耗时尚未测量，不承诺无条件加速。
- 收到的图片随原消息显示，点击可打开原图，或通过既有文件选择器保存。
  原图查看器处理 JPEG EXIF 方向；Runtime 缩略图同样处理方向。
- 设备的对话或任务交流页长按上键看图，上下键切图，确认键返回。
  查看器之外仍保留确认键翻页、双击菜单和长按说话。选图、上传在手机完成，
  本次没有添加设备相册或拍照流程。
- 设备只显示静态、等比留边的 **64×64 RGB565 缩略图**，不显示原图分辨率。
  每张卡最多提供最近四张图片，设备只缓存当前卡片的目录，切页后按需索取。解码和缩放在手机后台做；设备像素占用 8,192 字节，
  分配前要求另留至少 16 KiB 空闲堆；新增固定状态预算为 512 字节。不足时明确提示在手机看图。
- 主人上传限制为 8 MiB、1600 万像素，先经 Pillow 验证再登记。
  接收 PNG、JPEG、GIF、WebP，动图只显示静态预览。文件为不可变快照，保留在既有
  有容量上限的附件库；移除草稿不会删除已经保存的上传文件。
- 本轮仅支持主对话带图交给已配置的本地 **Codex**。当前纯文字聊天模型不会被当成
  已经收到图片。任务续聊、桌面会话、mesh 转发、其他模型以及录音与图片同时发送
  尚不支持；不支持的图片路由在受理前拒绝，原有纯文字和语音路由保持原流程。

## Runtime 约定

在 Runtime 使用的 Python 环境安装 `runtime/requirements-images.txt`。
`POST /v1/images` 使用现有 bearer 鉴权接收受限的图片字节，返回公开附件元数据，
不接收服务器文件路径或任意下载链接。

`POST /v1/messages` 新增 `image_ids`；只解析已登记的主人图片，确认受理前持久化
附件元数据，重试指纹包含有序图片身份和哈希。同一 `client_id` 换文字或图片返回 409。
`:you` 消息、卡片、同步和历史均保留附件；内容仍通过已有鉴权的
`/v1/artifacts/<id>/content`、`/thumbnail` 下载。

后台通过 `Job.images` 接收可信不可变快照路径：Codex exec 使用 `--image`，
app-server 使用 `localImage`。路径仅用于内部模型输入，不替换主人的公开消息正文。
替身测试不能证明真实模型已正确理解图片。

Windows 附件读取改为 CreateFile 句柄，检查最终句柄路径并拒绝重解析点和目录，
修复原先调用 Linux 专用 `O_DIRECTORY`、`O_NOFOLLOW` 的问题；不退化成有竞态的
先检查后打开。POSIX 仍沿用逐级不跟随链接的打开方式。

## 蓝牙约定

固件在既有 hub 应答声明 `"images":1`。仅在声明后发送图片协议；旧固件仍收原来的
文字协议。旧 Runtime 的上传接口会拒绝，因此不会把主人选好的图悄悄当成纯文字发送。

新增消息都是既有安全通道上的受限 UTF-8 JSON 行，不改 OTA 的 `0xFE` 帧通道和发送源。

| 方向 | `cmd:image` 操作 | 用途 |
| --- | --- | --- |
| 手机→设备 | `list`、`card`、`ids` | 将至多四个附件编号绑定到卡片 |
| 手机→设备 | `clear` | 切换 Runtime 或来源时清理图片状态 |
| 设备→手机 | `catalog`、`card` | 索取当前卡片的图片目录 |
| 手机→设备 | `catalog_error`、`card` | 当前卡片的目录不可用 |
| 设备→手机 | `get`、`card`、`id`、`token` | 按需请求已提供的图片 |
| 手机→设备 | `begin`、`id`、`token`、`size`、`crc` | 声明 8,192 字节及 CRC32 |
| 手机→设备 | `chunk`、`id`、`token`、`offset`、`data` | 每片至多 384 字节，经 Base64 编码 |
| 设备→手机 | `ack`、`token`、`next`、`status` | 逐片确认下一个连续偏移 |
| 手机→设备 | `end`、`id`、`token` | 只显示完整且校验正确的缓冲区 |
| 手机→设备 | `error`、`id`、`token` | 下载、解码或图片不可用 |

同一时间只传一张。连接代次与传输标识拒绝过期数据；手机每片最多重试三次，也限制
没有前进的确认。设备 15 秒没收到分片就放弃未完成缓冲区。关闭、换来源、离开页面、
语音或审批或升级抢占、断线时，持 LVGL 锁解除图片引用再释放内存。图片失败不能破坏
文字和固件恢复通道。

## 验证与回退

App 0.27.1 新增移除／重试后的过期回调、照片优化条件、预览尺寸与比例的主机测试。
手机验收需覆盖：取消选择、更换上传中的图片、断网失败与重试、旋转／页面重建、切换来源、
带 EXIF 旋转／镜像的照片、透明 PNG、仅图片／图文发送，以及回到语音。
同手机、同网络记录原图／优化后体积和选图到预览／就绪的耗时；这些指标与发送到首回复分开。

`runtime/tests/test_image_inputs.py` 覆盖登记、解码、鉴权上传收发下载、附件库重载、
重试身份、不支持路由和 Codex 原生图片参数。
`tests/test_pocket_images.c` 覆盖完整 CRC 传输、重复分片、非法元数据、超时、低内存、
连接代次失效；解码替身提供固定像素，实际固件链接 mbedTLS。既有门禁在 cJSON 可用时
执行该测试。

安装后的手机和设备显示、颜色、字形、语音共存、蓝牙重连、OTA 回退、真实模型看图与
多端收敛仍需实机证据。上传回执和转交提示不算有意义的模型首答，不能据此通过三秒首答
要求；应单独记录实际样本。

保留上一版兼容 App、Runtime 发布和已验证固件归档。本次不迁移分区或配对数据；
代码回退后新增附件元数据仍是既有产物。活跃 Runtime 的更新遵守原有重启审批规则；
发布 App 不等于手机已安装，蓝牙推送不等于硬件验收通过。
