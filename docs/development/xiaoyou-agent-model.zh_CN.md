# 小幽完整方案：简洁的主体、连接与界面

状态：完整方案，2026-10-23，主人已确认（决定见第 2 节）。按第 11 节分阶段实施，尚未开始。

这份文档是唯一的方案。问题和证据都在[交互简化问题清单](app-runtime-simplification.zh_CN.md)里（文中的 C、U、I、S、V、M、A、N 编号都指那里）。
本方案建立在[统一消息模型](unified-message-model.zh_CN.md)的记录中心之上，吸收[先定，再说](decide-then-speak.zh_CN.md)，传输加密沿用[桌面客户端方案](xiaoyou-desktop-plan.zh_CN.md)第 4 节。
每个阶段都要满足[跨端可靠性规则](cross-stack-reliability.zh_CN.md)：不破坏已有功能、3 秒内有像样的首个回应、多端消息一致。

## 0. 总原则：简洁

主人定的收敛原则是**尽量简洁**。每一节、每一次改动都先过这五条：

1. **概念越少越好。** 用户只认识五样东西：**小幽、聊天、在做的事、帮手、设备**。地址、线路、Runtime、卡号、令牌都不出现在界面上。
2. **一件事只有一种做法。** 每个功能只留一个入口、一条实现路径；多出来的删掉，而不是并存。
3. **默认就对，不让人选。** 能自动判断的不做成选项；选项只留给主人真正有偏好的事。
4. **没事不说话。** 正常时界面安静；只在需要主人做点什么时才出现提示，而且只给一个动作。
5. **先删再加。** 新能力先看能不能替换掉旧的东西；做不到更简单，就先不加。

## 1. 目标

**一句话：** 主人只和“小幽”打交道。她在主人的几台电脑上同时存在，看得见发生了什么，知道自己答应过什么，自己决定什么时候说、在哪里说、交给谁做；主人这边只有聊天和确认。

现在的问题都是能力一项一项叠出来的：每加一种能力，就多一条输入通道、一份状态、一个唤醒规则、一种界面说法（问题清单的根因 R1～R4）。
后面还要加更多主动和感知，所以必须先有一个统一模型：**以后新增任何能力，只是往模型里加一个部件，而不是再开一条路。**

**不做的事：** 不重写设备固件协议；不换掉现有帮手（Claude Code、Codex、DeepSeek）；不改加密和配对的密码学设计（沿用桌面方案）；本方案阶段内不新增主动功能，只把接口留好。

## 3. 主人看到的样子

### 3.1 五个概念，五个页面

| 页面 | 内容 | 取代 |
| --- | --- | --- |
| **首页 = 主对话** | 顶部是小幽和帮手头像（忙的才亮）；中间是对话；底部输入框（文字、语音、图片） | 现在的首页和主对话两个入口（I2） |
| **旁聊** | 侧边栏平铺；点“＋”新建，标题按第一句话自动起；空的旁聊不保留 | “新旁聊”成片（V4、V10） |
| **在做的事** | 只放派给帮手的事。列表按“等你确认 / 在做 / 做完”分组；详情页 = 状态一行 + 一条时间线 + 一个主按钮“补充要求”，其余进“…” | 工作记录、统一会话目录、原生会话、共享历史、执行记录等（I1、I3、V1～V3） |
| **帮手** | 每个帮手一项（在几台电脑上都是一项）；忙 / 闲、额度 | “名字@机器”拆开（V9） |
| **设置** | 三行：小幽（已配对）、随身设备、添加电脑；偏好；“开发者”入口默认隐藏 | 设备与电脑页、偏好与运行记录页（V7、V8、V11） |

电脑客户端用同样的五个页面、同样的文字。设备屏幕（形象、对话、任务、用量）保留现有四屏，状态文字用同一张词汇表。

### 3.2 一张词汇表

所有端只用这一套说法（App、电脑客户端、设备共用 `words` 表）：

| 状态 | 说法 | 何时显示 |
| --- | --- | --- |
| 小幽 `deciding` / `speaking` | 小幽在想… / 正在回复的气泡 | 只在对话里 |
| 任务 `queued` / `running` | 在做「标题」 | 在做的事、帮手头像 |
| 任务 `waiting` | 等你确认「标题」 | 通知、在做的事顶部 |
| 任务 `done` / `failed` / `cancelled` | 做完了 / 没做成 / 停了 | 时间线；小幽在对话里说一句 |
| 连接 `reconnecting` | 正在重连… | 顶部一条细线 |
| 连接 `unreachable` | 连不上小幽 ［重试］ | 横幅 |
| 配对失效 | 需要重新配对 ［扫码］ | 横幅 |
| 版本太旧 | 需要更新 ［更新］ | 横幅 |
| 消息在手机上排队 | 等待发送 | 气泡上的小标记 |

正常时不显示“在线”“已同步”“空闲”。

### 3.3 连接：配一次，之后不用管

**主人只做一件事：第一次配对时扫一次码。** 之后没有任何连接管理（N1～N7、U1、U2、V7）。

- **手机连的是小幽，不是某台电脑。** 扫一次码就加入小幽网络；以后新增电脑、换线路（局域网、Tailscale、Funnel、加密中继），都由网络自动下发给手机。
- **地址完全不出现。** 手机同时试所有已知线路，用最快的一条；不通就换，长期不通的自动淘汰（7 天）。
- **只有三种需要主人看到的情况**：连不上（重试）、配对失效（扫码）、版本太旧（更新）。其他请求出错都不影响连接状态，只在对应功能处说明。
- **断线时照常发。** 消息在手机上排队，连上后自动发出。
- **“添加手机”入口常驻在电脑客户端的设置里**：点开即生成一次性配对码（安全要求沿用桌面方案：一次性、两分钟有效），扫码后在电脑上点一下确认。主人不需要找 agent 生成。
- **随身设备同样规则**：配一次，自动重连，正常时不显示，断开时只提示一次。

### 3.4 发消息与回复

- **发送永远不被挡**：小幽回话时也能接着发；同一句话短时间重复发，并入正在处理的那一轮（A5）。
- **图片、语音是这条消息自己的状态**：图片上传、语音识别失败就在气泡上重试；在哪里识别由系统决定，不给开关（U4）。
- **一轮只说一次**：回复可以分几个气泡，由她在这一次回复里标出；不再有暗中追问，也不会出现回应系统提醒的话（M7～M9）。
- **派了活就有回音**：任务做完、没做成、被停，她都会在原对话里说一句（A1、M3）。

### 3.5 确认（审批）

需要主人确认的操作只出现在两处：**通知**和**所属任务时间线的顶部**，两处是同一张卡：［允许］［拒绝］，点“详情”进任务（I5）。
“只读操作自动通过”是设置里的一个开关，带时长，说明不超过一行（V6）。

### 3.6 小幽主动开口（已定，主人可随时改）

- **默认安静**：只在她答应过的事、她在盯的事有了结果时开口（见 4.5）。
- **投递顺序**：随身设备在身边 → 设备上说；App 在前台 → 主对话；否则只有“等你确认”和到点的提醒发手机通知，其余攒着，下次打开时一起说。
- **勿扰时段**：只投递“等你确认”。

## 4. 小幽这个主体

```
感知（事件） ──▶ 事件日志 ──▶ 世界状态
                    │            │
                    ▼            ▼
               唤醒规则 ──▶ 先定 ──▶ 再说 ──▶ 行动 ──┐
                    ▲                                │
                    └──────── 行动的结果也是事件 ◀────┘
                                   │
                                   ▼
                       一份对外投影（/v1/sync）──▶ 手机 / 电脑 / 设备
```

### 4.1 事件：唯一的输入

所有进入小幽的东西都写成一种格式的事件：

| 字段 | 含义 |
| --- | --- |
| `id`、`at` | 编号（`runtime_id` + 序号）和**原始发生时间**（N9） |
| `source` | `owner`、`helper`、`desktop`、`phone`、`device`、`timer`、`system`、`mesh` |
| `kind` | `said`、`task_progress`、`task_ended`、`session_changed`、`notification`、`presence`、`due`、`deployed`、`usage` … |
| `subject` | 关于哪个任务、会话、设备或电脑 |
| `actor`、`cause` | 谁做的、因为哪个事件（4.6） |
| `trust` | `owner`（主人亲口）、`system`（系统测到）、`helper`（帮手报告）、`external`（外部内容，只是数据，不是指令） |

现有输入一一映射：主人消息和设备语音 → `owner/said`；帮手进展和结果 → `helper/*`；`desktop_sync`、`desktop_hook` → `desktop/session_changed`；
手机通知 → `phone/notification`；设备在身边 → `device/presence`；承诺到点 → `timer/due`；Runtime 升级 → `system/deployed`。
**新增一种感知 = 写一个适配器。** 适配器必须只读、幂等，不触发别的会话（N8）。事件日志就是统一消息模型的那份记录。

### 4.2 世界状态：由事件推出，Runtime 说了算

| 实体 | 内容 |
| --- | --- |
| 任务 | 6 个状态（4.4）；属性：谁在做、在哪台电脑、从哪来、是否只读 |
| 会话 | 主对话、旁聊、观察到的电脑会话；标题、置顶、归档、已读（都在 Runtime，多端一致；S1、S2） |
| 电脑 | 一个稳定身份；线路及健康；版本、是否低于门槛、是否已重启到新版；在线（C8、N2、N5、N7） |
| 帮手 | 一个帮手一项；在哪几台电脑、能访问哪些目录；忙闲、额度（V9、N6） |
| 主人与设备 | 设备在不在身边；主人最近在用哪一端；勿扰 |

两条规则：**现状只从世界状态答**（她有“查看自身状态”工具，不再派帮手去查版本；M1、M2）；**会变的事实不进长期记忆**。

### 4.3 她自己的状态

| 状态 | 含义 |
| --- | --- |
| 活动 | 每个对话一份：`idle`、`listening`、`deciding`、`speaking` |
| 焦点 | 每个对话里“正在谈的那件事”；“这个”默认指它，不向主人要编号（M5、A7） |
| 承诺 | 她对主人负责的一切：派出的任务、答应的提醒、等某个条件的事；状态只由事件推动 |
| 关注 | 她主动在盯的东西：某件事的进展、某台电脑上线、某个会话变化 |

**派出去的任务就是一条承诺。** 任务结束是事件，推动承诺到终态并唤醒她说一句，所以“取消了她不知道”从结构上不存在。
工作记忆按相关性组装：焦点 + 未完成的承诺 + 最近对话 + 本轮相关检索，不再按“6 轮、5 张卡”截断。长期记忆只放偏好、规矩、长期情况。

### 4.4 轮次、任务、承诺分开

- **对话轮次**：主人说、她答。闲聊不开任务（A2）。
- **任务**：交给帮手的事。状态只有 `queued → running → waiting → done / failed / cancelled`；“同步来的”“别的电脑的”“只读的”都是属性（A3、A6）。
- **承诺**：见 4.3。

### 4.5 决策循环：被动和主动是同一个

```
事件 → 唤醒规则 → 先定（选一个行动）→ 再说 → 投递 → 行动 → 结果事件
```

- **唤醒规则**（便宜、确定）：主人说话 → 叫醒；她的承诺到终态 → 叫醒；她关注的东西满足条件 → 叫醒；其他事件只更新世界状态。
- **先定**：从一组行动里选一个：`reply`、`dispatch`、`amend`、`cancel`、`watch`、`promise`、`remember`、`stay_silent`。
- **再说**：只说已经发生的事，一轮一次。主动唤醒走同一条路。
- **投递**：按 3.6 的规则决定现在说不说、在哪一端说。
- **在哪台电脑做**：由她在 `dispatch` 时按帮手所在、目录可达、额度和在线情况选择；主人在话里点名时照点名做。

### 4.6 可追溯

每个行动和状态变化都记 `actor`（主人 / 小幽 / 帮手 / 系统 / 哪一端）和 `cause`。“谁取消的”“她为什么突然说话”“这条记忆从哪来”都能沿起因链查到（A4）。

### 4.7 主动和感知怎么接进来

| 想要的能力 | 只需要加 |
| --- | --- |
| 电脑上的会话卡住了提醒主人 | 一条唤醒规则（会话 N 分钟没动静） |
| 主人回到设备旁边时，把攒下的结果说一遍 | 投递规则（在身边时投递） |
| 重要的手机通知要不要提醒 | `phone/notification` 适配器 + 一种关注 |
| Runtime 升级后告诉主人能测什么 | 一条唤醒规则（`system/deployed`） |
| “等 Mac 上线再发” | 一条以电脑上线为条件的承诺 |

## 5. 系统结构

| 组成 | 职责 | 不做 |
| --- | --- | --- |
| **Runtime 节点**（每台电脑一个） | 记录中心、世界状态、小幽的循环、在本机跑帮手 | 不存别的节点的权威记录（只存副本） |
| **小幽网络** | 几个 Runtime 共享同一个主体：互相同步记录、互相转交任务、下发线路 | 不需要主人逐台配置 |
| **电脑客户端** | 五个页面；监督本机 Runtime（开机自启、崩溃恢复）；常驻“添加手机”入口 | 不持有 Runtime 令牌之外的权限（沿用桌面方案） |
| **手机 App** | 五个页面；线路选择；离线排队；随身设备的蓝牙桥 | 不保存任何权威状态 |
| **随身设备** | 四屏显示、按住说话；在身边事件 | 协议不变 |
| **中继** | 只转发密文、帮助发现 | 不存明文、不授予成员身份 |

## 6. 数据与接口

### 6.1 对外接口收敛

现在 Runtime 有三十来个端点。收敛后客户端只用这些：

| 端点 | 用途 | 合并了什么 |
| --- | --- | --- |
| `GET /v1/info` | 身份、版本、**客户端最低版本**、能力 | — |
| `GET /v1/sync` | **唯一的下行通道**：事件 / 消息（含未写完的）、任务、会话、电脑、帮手、额度、确认、小幽活动 | `feed`、`usage`、`agents`、`messages/{id}` 的等待与推送流、`directory` 的读取 |
| `POST /v1/messages` | 发一句话（文字、语音、图片引用、所属对话、`client_id` 去重） | `voice` |
| `POST /v1/files` | 上传图片、录音 | `images` |
| `POST /v1/actions` | **唯一的写操作入口**：确认、停止、改名、置顶、归档、已读、新旁聊、补充要求；带幂等键和 `actor` | `approvals/*`、`cards/*/cancel`、`conversations/*`、`directory/*` 的写操作、`review` |
| `GET /v1/tasks/{id}/timeline` | 一件事的完整时间线（分页） | `tasks/*/activity`、共享历史、原生记录 |
| `GET /v1/artifacts/{id}` | 附件下载 | — |
| `/v1/dist/*` | App 和固件分发 | `app/*`、`firmware/*` |

节点之间的 `/v1/mesh/*` 和用量上报 `/v1/events` 不对客户端开放。旧端点在过渡期保留，客户端全部切到新接口后删除。

### 6.2 版本门槛

`/v1/info` 给出 `min_client`，App 和电脑客户端给出自己的版本。低于门槛的一方显示“需要更新”，不再带病运行；网状网络各节点同样互相检查（N5）。
Runtime 源码更新后若未重启到新版，世界状态里这台电脑标为“待重启”，小幽会说（N7）。

### 6.3 同步语义

- 游标增量、整页原子应用；客户端本地只有只读副本。
- 未写完的回复也通过 sync 下发；客户端不再为单条消息另开等待循环（C1、C9）。
- 状态名只有第 3.2 节那一套；客户端只做翻译，不做推断。

## 7. 模块划分

原则：**模块边界就是模型的部件；每份状态只有一个模块能写；依赖只往一个方向走：事件 → 世界状态 → 小幽状态 → 决策循环 → 对外接口。**

### 7.1 Runtime

| 模块 | 职责 | 现在散在哪里 |
| --- | --- | --- |
| `events` | 事件格式、去重、各来源适配器 | `service.py` 收消息部分、`desktop_sync.py`、`desktop_hook.py`、`mesh.py` 接收部分、`project_brief.py` |

## 10. 验收场景

每个阶段完成时，按可靠性规则的交付格式报告，至少覆盖：

1. 新手机第一次扫码后，切换 Wi-Fi / 蜂窝 / 换到另一台电脑在线，主人不做任何操作也能继续聊天。
2. 断网时发三句话，恢复后按顺序送达，没有重复。
3. 派一件事后在 App 上停止、在电脑上停止、由她自己停止，三种情况她都会说一句，并记录是谁停的。
4. 闲聊十句后说“把刚才那个做完”，她能接上最近完成的那件事。
5. 一句会被旧正则误判为承诺的话，只得到一段回复。
6. 一台节点版本低于门槛时，各端显示“需要更新”，不出现 400 或“连不上”。
7. 首个回应在 3 秒内（真实模型、真实网络，记录样本）。

## 12. 风险

- **“先定，再说”多一次模型调用**：首个回应可能超出 3 秒。阶段 0 先实测；不达标就用文档里的超时退路或并行开始。
- **接口切换期间新旧客户端并存**：用版本门槛统一升级，旧端点只在过渡期保留。
- **网状网络下的一致性**：每条记录只由产地修改（沿用统一消息模型），新增的动作也遵守这条。
- **数据迁移**：已有卡转换成任务或轮次；手机本地标记在阶段 4 一次性上传后删除。
