# 人设与执行能力的边界

## 本次拆分

`runtime/persona.txt` 只保留身份、关系、语言、性格、表达长度和口吻示例。
`runtime/xiaoyou_runtime/loop/prompt_rules.py` 接管原人设中的做事、授权、真实性、进度、记忆、主动性和消息分隔规则。
聊天（工具和 JSON 两种模式）、结果转述、以角色身份执行的后台任务、主动提醒和记忆整理都组合这份固定规则。
普通工作帮手仍只接收任务，不强加角色口吻。人设配置字段及配置文件格式不变。

这是保守的职责迁移，未删除原有做事规则，也未引入动态模块检索。
原人设 4,348 字符，拆分后 964 字符，固定规则 3,399 字符；总输入没有因此降低。
工具描述也占上下文，不能将文件拆分当作 token 或缓存收益。
换人设时保留既有工具、执行检查、授权和任务状态规则；人设本身仍可能影响模型的选择，不能保证任意人设都表现相同。
本次未重启或部署正在运行的 Runtime。

## 需要主人提供的信息

不用写系统提示词，按下面的项目描述即可；没想好的留空。

| 项目 | 需要描述的内容 |
| --- | --- |
| 身份与存在方式 | 名字、是什么、住在哪里；外形只作背景；能感知什么，哪些经历不能编造 |
| 关系 | 伙伴、朋友或其他关系；如何称呼你；亲密、依赖、玩笑的边界 |
| 性格与判断 | 三至五个核心特征；喜欢什么、讨厌什么；什么时候有自己的意见 |
| 情绪回应 | 你吐槽、低落、开心、沉默时，希望先接情绪、一起吐槽还是给建议；温柔与调侃的尺度 |
| 语言与节奏 | 口语程度、长短、气泡数量偏好、反问频率、表情和语气词；避免的口癖 |
| 自身偏好 | 少量有原因的喜好和好奇心；允许变化；不要靠每次提同一个物件来表现个性 |
| 主动性 | 什么线索下可以关心或提建议，什么时间不要打扰；具体提醒交给约定工具 |
| 对照例子 | 五至十段“你说的话／喜欢的回应／不喜欢的回应／原因”，优先给自然表达 |
| 给别人用 | 哪些属于角色共性，哪些只是你的称呼、偏好、关系和记忆；后者放每个用户自己的设置或记忆 |

不需要你编工具名、任务编号、调用格式、执行步骤、权限条款、模型档位或成功判定。
这些由 Runtime 和实际能力提供。对外发送、购买等授权不能由角色“很主动”代替。

## 现有调度覆盖与不能声称的能力

以下按当前源码核对；“有入口”不等于已安装的帮手在真实服务上执行成功。

| 需求 | 已有入口 | 边界 |
| --- | --- | --- |
| 交办、追加、修改、取消、查进度 | `start_task`、`amend_task`、`cancel_task`、`task_detail` | 保留原执行校验、任务身份和后台生命周期；每轮仅一个行动 |
| 旧对话和工作记录 | `recall` | 只覆盖当前可索引、获准的记录；不等于任意跨机器文件读取 |
| 用户长期偏好、改口、忘记 | `remember`、`replace`、`forget` | 用户记忆与角色共性分开，成功后才确认 |
| 到时提醒、重复提醒、结束约定 | `track`、`resolve` | 到期由后台调度唤醒；需要工具模式、后台循环和正确时区；不是完整外部日历 |
| 文件、命令、网页、平台操作 | 交给实际配置的帮手 | 依赖帮手的连接器、权限、主机和在线状态；本地调度入口不证明外部能力已接通 |
| 图片、语音、表情与附件 | 已有输入、显示、产物链路 | 格式和客户端支持属于程序；不能靠角色文本新增感官或显示能力 |
| B 站、虚拟手机、QQ 群管 | 可交办给有能力的帮手 | 没有对应原生角色工具；不能直接照搬开源人设中的工具名并宣称可用 |
| 条件触发、持续观察 | 约定记录与帮手后台任务 | `track` 本身不是任意条件检测器；条件检查与重试需要具体执行器，尚无通用条件监视保证 |

工具参数、用法放工具 schema；复杂平台步骤可以放帮手按需读取的技能或说明。
身份、关系和情绪反应保持常驻。权限、真实性、执行结果校验保持固定规则和程序检查，不能按场景省掉。
时间、任务状态、实际工具清单、当前主机、用户记忆由 Runtime 动态提供，不写进人设。
如果以后实现按需资料加载，需要真实检索入口、找不到时的回退和延迟验证；当前没有新增这个入口。
