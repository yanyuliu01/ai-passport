## 2. 先修的两个 bug

### 2.1 有标题的旁聊打开后是空白页

「重构联调测试：只回复“同步验证通过”…」和「重构桌面显示测试：只回复“桌面同步…”」这两段旁聊有标题和更新时间，打开后却显示「想聊什么直接说 / 标题会按你的第一句话自动起」，一条消息都没有。其他四段旁聊正常。这两段可能是在 Windows 上做同步测试时建的，目录元数据同步到了 Mac，消息却没过来。**这是推测，未经核实。**

要求：

1. 先到 Mac Runtime 上查这两个会话有没有消息，确定数据丢在哪一层：Runtime 本身没有，还是同步到手机的缓存（`SyncCache` / `ChatHistory`）没拉到，或者手机拉到了但没有显示。
2. 修的是手机这一侧的问题，就直接修。如果消息只存在于另一台电脑，手机要明确提示「这段记录在 X 上，还没同步过来」。**不要**对有标题、有更新时间的会话显示新旁聊的空状态。
3. 双端历史同步本身是另一个已知问题，不在本次范围内。如果查下来是同步的问题，记录下来报告即可，不要顺手去改 Runtime。

### 2.2 旁聊打开后停在最早的消息

`MainActivity.onHubChanged()` 只有在刷新前已经在底部（`atBottom`）、并且有新消息（`grew`）时，才会调用 `scrollDown()`。`atBottom` 用的是上一段对话的滚动位置，所以切换到另一段对话后会停在最上面。

要求：通过 `enterConversation()`、`openMainChat()` 或返回进入某段对话后，等首屏内容画完就定位到最新一条消息。分页拉取历史时（`catchingUp`）也要在拉完后落到底部。用户自己往上翻过之后，就不要再强制拉回底部。

## 3. 侧边栏重排（主人已确认）

和桌面端 `companion/desktop/src/ui/app.tsx` 的 `<aside className="sidebar">` 对齐。桌面端的结构是：上面固定，中间的旁聊区单独滚动，帮手和设置固定在底部。

```text
┌ 固定 ───────────────────────┐
│ 小鱼头像 · 小鱼 · ● 已连接     │  ← 连接状态只在这里显示
│ 主对话                        │
│ 在做的事               [2]    │
│ 旁聊                    ＋    │
├ 单独滚动 ───────────────────┤
│ 📌 置顶的旁聊…        11:52   │
│ 旁聊标题…                ●   │
│ …                            │
│ 已归档 1                     │  ← 列表最后一行小字链接
├ 固定在底部 ─────────────────┤
│ 帮手                    ＋    │
│ (Codex)  Codex       空闲    │
│ (Claude) Claude      在做    │
│ ───────────────────────────  │
│ ⚙ 设置                       │  ← 去掉右侧的「已连接」
└─────────────────────────────┘
```

逐项说明：

1. **帮手移到设置上方。** 主人的意思是帮手本质上属于设置。帮手标题、帮手行和设置共用底部固定区，帮手标题上方加一条细分隔线。帮手太多时，帮手区限高后单独滚动，桌面端用的是 `max-height: 220px`，手机上按 3 行左右处理。帮手标题旁的「＋」保留，这是主人之前明确要的，桌面端没有这个按钮，这个差异保持不变。
2. **旁聊区单独滚动。** 和桌面端一样，旁聊显示全部，不截断成「最近几条」。「已归档 N」从现在像导航入口的大行，改为旁聊列表最后一行的小字链接。
3. **所有行统一样式。** 「主对话 / 在做的事 / 设置」改用和旁聊相同的 `listRow` 底：同样的左边距和圆角，都有按压反馈。现在的 `groupRow` 没有按压背景，图标还比旁聊文字靠左一截。字号统一为 14。旁聊行左侧要对齐，可以留一个图标宽度的空位，或者统一不放图标，两种都行，但要整齐。
4. **当前所在位置要高亮。** 停在主对话（语音页和文字页都算）、在做的事、设置时，对应行使用和选中旁聊相同的浅蓝底 `0xffeef4ff`。桌面端对应的是 `.selected`。
5. **时间和未读分开显示。** 时间单独占一列，未读蓝点放在时间左侧或标题右侧，不能再替代时间。时间格式：今天显示 `HH:mm`，昨天显示「昨天」，今年内显示「M月d日」，更早的显示「yyyy/M/d」。标题和时间之间至少留 8dp。
6. **连接状态只显示一次。** 顶部的小鱼身份块保留「● 已连接」，用绿点或灰点表示状态。底部设置行右侧的 `drawerState` 去掉。
7. **帮手状态的文字和颜色。** 状态集合沿用桌面端：等你确认用橙色，在做用蓝色，空闲和连不上用灰色。手机特有的「电脑上在跑」保留，用蓝色。现在 `stateText()` 把除了确认和未知以外的状态都画成蓝色，要改成按状态分色。
8. **头像上的额度圈。** 现在 Claude 头像上那一小段红色弧线没有任何说明。参照桌面端 `.quota-value`，在头像下方叠一个很小的剩余百分比标签，或者长按、点击帮手时在额度面板里说明。至少要让人看得出这是额度。

不要改的：长按菜单、多选、全选、批量归档、删除确认，这些 0.37.3 已在真机上验收过。不改桌面端代码。

## 4. 图片发送：对齐微信（主人已确认）

主人原话：「图片上传不太行，这个就对齐微信吧」「交互也要改」「我选中之后可以直接发出去吧，别搞得非要上传完才能发」。

### 4.1 已修好的传输问题（已提交）

在 0.37.4 之前，走服务器中转时图片一张都发不出去，原因有三层：

1. 手机上传时把内容类型写成 `application/octet-stream`，而桌面端中转（`peers.ts` 的 `allowedRPC`）只放行 `image/jpeg|png|webp`。现已改为发送真实类型，HEIC、GIF 等格式转成 JPEG。
2. `RelayConnection.tick()` 每秒都把所有未确认的包重发一遍，大包在上行带宽里越堆越多。超时的图片上传还作为「待确认写入」每 5 秒重放一次。现已改为：等发送队列清空后才重发，大包至少间隔 10 秒；图片上传不再作为待确认写入保存。
3. 桌面端中转对 `/v1/messages` 的字段白名单里没有 `image_ids`，所以带图片的消息一律被拒，错误又被统一包成「409 记录不匹配」。现已在桌面端 0.1.20 里放行 `image_ids`（1 到 4 个），并改为返回真实的错误原因。

另外按微信默认（非原图）的做法压缩：照片长边 1920，单张不超过 1MB；长截图按总像素限制，保证字能看清；原图读取上限放宽到 40MB。原因是桌面端每个中转请求最多等 30 秒，图片太大在手机网络上传不完。

真机结果：三张测试图（11MB 照片、17MB 噪点长图、截图）在 0.37.4 上 18 秒内全部传完。装上 Mac 桌面端 0.1.20 后，在临时旁聊里发出的带图消息正确归到了这段旁聊，小鱼收到了图片（随后把看图交给 Codex，Codex 当时额度用完）。

### 4.2 要做的交互

1. **选中即发。** 在系统选图器里点「确认」后，所选图片立即作为我的消息出现在聊天里：右侧蓝色一侧，显示按比例缩放的缩略图，上面叠加上传进度。不再有输入框上方的草稿条，也不用等上传完再点发送。后台按顺序上传，全部传完后自动调用 `POST /v1/messages`，`text` 为空，Runtime 会补上「请看看这些图片」。输入框里正在写的文字不跟图片一起发，留在输入框里，和微信一样。
2. **一次选多张。** Runtime 每条消息最多收 4 张图（`image_inputs.MAX_IMAGES`）。选图器上限放到 9 张，超过 4 张时自动拆成几条消息，每条最多 4 张。
3. **发送状态显示在气泡上。** 上传中显示进度；失败时在气泡左侧显示红色感叹号，点一下重发。离开页面或切换旁聊后，后台队列继续传；App 被杀掉后，未完成的图片消息显示为失败、可以重发。不要静默丢弃。
4. **已发图片的显示。** 现在已发的图片显示成文件卡片（「图片 · 图片.png 0 B · image/png」加一个「查看原图 / 保存」按钮），而且显示在左侧，看起来像对方发来的消息。改为右侧的纯图片气泡（圆角，不加文字说明）。点开进入全屏查看：双指缩放，左右滑动查看同一条消息里的其他图片，长按可以保存。
5. **「＋」面板。** 「添加附件」底部面板里的「文件」目前是无法使用的选项，先去掉。改成微信那样的图标网格：「相册」「拍摄」。「拍摄」调用系统相机，拍完直接走第 1 条的流程。
6. **原图开关（可选）。** 微信有「原图」开关。中转单次上限约 2.8MB、30 秒，暂时不做；如果要做，必须先改桌面端的超时和上限。

只改 `companion/android`。0.37.4 的传输修复（`ImagePreparation`、`ImageUpload`、`RelayConnection`、`RuntimeClient.uploadImage`）保留，不要回退。
