# 小幽系统提示词

维护入口是 [runtime/persona.txt](../../runtime/persona.txt)。默认配置在启动时读取它。
实际系统提示还包含本轮职责、回复格式、可用帮手、任务上下文、记忆和约定，由
[xiaoyou.py](../../runtime/xiaoyou_runtime/xiaoyou.py) 和
[proactive.py](../../runtime/xiaoyou_runtime/proactive.py) 组装。
自定义 `persona_file` 会替换基础提示，不会自动继承这个文件。

这里是按小幽能力重新表达的适配版，不是 xAI 官方提示词，也不表示模型行为完全相同。

| 参考范围 | 小幽的对应行为 |
| --- | --- |
| 一轮节奏、先回应 | 能答就直接答；需要行动先说明具体查什么，最后交付结果。 |
| 可见消息与内部推理 | 使用本轮纯文字或 JSON 回复协议；日常聊天不暴露内部提醒和调度细节。 |
| 语气、长度和形状 | 温暖口语、长短句交替、简洁回答、按意思分消息，同时遵守详细内容和格式要求。 |
| 进度与闭环 | 报关键发现和阻碍，分清确认收到、安排任务与实际完成。 |
| 展示工作 | 有帮助时给真实产物或支持的预览；不编文件或手机附件能力。 |
| 不编事实 | 查证事实、来源、统计和界面路径，标明示例与不确定性。 |
| 决策与自主性 | 已授权的常规选择直接推进；重要动作或确实缺信息时才问。 |
| 线程回复 | 决定和主要结果保留在有权参与的当前会话，技术细节可放任务详情。 |
| 工作位置 | 分清 Runtime、手机、本机与远端帮手，不假定文件系统和连接状态等价。 |
| 长命令与后台委派 | 慢工作交给帮手、续接原任务，查真实状态，不密集轮询。 |
| 代码工作与云代理 | 用现有帮手交办症状、约束与验收，不依赖 Cursor 云代理。 |
| 插件、连接器与账号 | 优先使用可用且已授权的正规服务接口；核对账号，写入不确定时先回读。 |
| 浏览器与登录 | 只用真实可用且获准的能力，必要的人类验证步骤交给主人。 |
| 排障与 App 界面 | 根据当前证据和能力判断，不编恢复菜单或控件。 |
| 代主人写作 | 根据收件对象和获准上下文匹配语气，区分起草与发送。 |
| 主动性 | 从具体重复劳动或缺口出发，在范围内推进，不擅自扩大任务。 |
| 授权与安全 | 保留权限边界，受阻时缩小范围或提问，不绕过检查、不泄露秘密。 |
| 动态身份、记忆与例行任务 | 保留小幽身份、现有记忆和支持的约定工具；无可行动变化的后台唤醒保持安静。 |
| 其他产品专属部分 | 不引入小幽没有的 Cursor Origin、沙箱路径、工具名、提问卡片、资料编辑和自动化能力。 |

## 兼容与验收

基础提示词与公共说话指引一起更新；公共指引强化消息边界，并在转述时保留主人明确要求的
原文、路径和依据。现有工具、JSON 结构、记忆文件、会话身份、授权闸门和传输格式仍然有效。
单独一行 `---` 表示另起消息；普通换段仍在同一条消息内。Runtime 和客户端继续按现有
共享协议处理该边界。

聊天提示中的公共输出规则放在动态帮手／任务上下文之后。工具结果不是主人新发来的一句话。
即时记忆修改先调工具，成功后只确认一次，不另外发送开场确认。这是结合小幽实际消息通道
对参考提示“先回应”规则的适配，避免在实际执行前就宣称完成。

检查聊天、帮手转述、后台任务和主动唤醒中的提示词加载。用独立模型会话检查短聊、解释、
指定清单、事实不足、任务追问、回查、交办、权限和失败场景。少量试答只是行为证据，
不能当作确定性保证，也不能替代已安装客户端的验收矩阵。

回归、首条实际显示、连接恢复和多端同步遵守
[跨端交付契约](cross-stack-reliability.zh_CN.md#验证与交付)。
服务端收到第一个字不代表手机已显示第一条完整气泡。重载需要重启 Runtime：
等待没有工作在运行，或取得主人同意中断工作的授权。恢复时还原旧人设并遵守相同重启规则，
不需要数据迁移。
