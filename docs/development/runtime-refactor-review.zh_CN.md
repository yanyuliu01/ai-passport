## 1. 结论及保留项

三层结构和渐进迁移可以继续。保留：统一写入入口；先持久化再产生后续效果；接收进度与投影应用进度分开；快照加增量；流控；请求身份去重；来源隔离；配对绑定主机身份；通知与状态同步分开；会话分段不复制承诺或任务。

必须修正的是借鉴时遗漏的成立条件，尤其是“超时就自动换负责人”。不用 Raft 是可选的架构决策，但“两三台电脑所以多数派没有意义”不是单写者安全性的证明。

## 2. 阻止自动接管的缺口：谁有权更换负责人

**当前条款不能直接实现：**“谁收下第一句谁负责，心跳超时后另一台接管，令牌加一”。

反例：Mac 与 Windows 互相断网，但都能访问模型和工具。Windows 认为 Mac 离线而接管，Mac 仍认为自己有效。两边各自把令牌从 7 加到 8，并不能让其中一边失去执行资格。首次收到消息也不能在网络分区时形成全局一致的先后顺序。

### 第一版默认行为

- 对话绑定一个持久、明确的负责人；同一对话的首次绑定必须通过指定权威完成，不能由各节点独立猜测。
- 网络超时只说明不可达，不证明原负责人已停止。不能仅凭超时把同一对话交给另一台执行。
- 无法确认安全交接时保留请求及原编号，显示排队/负责人不可达；区分本地待发与权威已接收，不声称任务已开始。
- 固定负责人方案不承诺原负责人失联后的自动可用性。旧任务不自动迁移；按操作身份查询，无法核对的标为结果不明。
- 人工点“接管”也不能自动消除旧机器仍在执行的风险；交接仍须满足下面的隔离条件。

### 自动接管前必须明确的契约

| 问题 | 必须写明的答案 |
| --- | --- |
| 谁发放令牌 | 一个明确的、持久化的协调权威，或有安全性保证的协调协议；不能每台自行加一 |
| 如何授予 | 对负责人、旧代次、新代次进行原子检查和更新；同一请求重复提交返回同一授予结果 |
| 谁拒绝旧令牌 | 权威写入路径及实际动作执行边界；仅客户端或 `Loop.step` 开始时检查不够 |
| 检查时机 | 提交决定、派发动作和发布回复前检查有效代次；检查与提交不能留下允许旧代次写入的竞争窗口 |
| 模型调用跨越交接 | 将模型结果绑定原操作及负责人代次；失效结果可留作审计，但不能成为新回复或新动作 |
| 外部工具不支持令牌 | 阻止旧执行者继续派发；已开始且不能隔离的动作必须核对，不能声称绝无重复副作用 |
| 协调方失联或重启 | 写明是否停止授予/执行、如何恢复已授予记录；不能静默降级为各节点自己决定 |
| 租约和时钟 | 若采用租约，定义单调时钟、漂移假设、睡眠/重启和过期处理；心跳超时不能替代完整规则 |

暂不在本文件指定新服务器或引入 Raft。先落实保守行为；有明确协调方案及故障测试后，再启用自动接管。R4 必须定义并落实授予和写入隔离，R6 接入模型/执行路径；不能 R4 先自动切换、等 R6 才拒绝旧执行者。

## 3. 日志代次与负责人代次必须分开

- `log_epoch`（可沿用现有协议字段 `epoch`）：标识某个产地的日志历史代次，用于判断游标是否还能接续。
- `owner_generation`：标识某个对话的负责人授予代次，由协调权威管理，用于拒绝旧执行者。
- `accepted_seq` / `applied_seq`：同一产地、同一日志代次中的持久接收位置与投影应用位置；本地持久接收不是 Raft 的多数派提交。

这些名字是概念区分，不要求立即重命名现有兼容字段。普通重启不应无故重置持久身份或代次。多产地进度按 `(origin, log_epoch, seq)` 跟踪，不能拿两台电脑各自的数字比较谁更新。

发现同步缺口时，优先补齐仍保留的增量；游标失效或增量缺失才切快照。快照固定在 S，S 之后的增量使用有界保留窗口；慢客户端超期后重新取快照，不能为了等待所有客户端无限保留日志。

## 4. 确定性核心不包含重新调用模型

R3 可直接继续：把状态归约做成“旧状态 + 已保存事件 → 新状态/待执行意图”。时钟、随机身份、模型返回、网络结果、工具结果是显式输入；需要恢复的输入应被保存。

- 重放不调用模型、不执行工具、不发送通知，也不重新生成决定。
- 模型请求和工具执行由外层驱动；返回结果作为事件进入状态机。
- 投影状态和 `applied_seq` 必须一致保存；重启后从正确位置应用，不能仅保存一个超前游标。
- 固定随机种子只是辅助；测试还必须控制时钟、网络投递与故障位置。保存失败种子及必要事件轨迹以便复现。
- 模拟覆盖丢包、重复、乱序、分区、崩溃；保留真实线程、磁盘、HTTP 和跨端集成测试。模拟测试不替代并发或真机验证。

R3 原有崩溃边界仍须覆盖：持久接收前、接收后执行前、外部动作可能开始但结果未提交、结果已提交但回执丢失。已开始但结果不明的外部动作不能通过重放自动重做。

## 5. 新节点及成员变更的边界

新节点接某段对话之前，追上的是**该对话在明确截点的必要状态**：消息、待办、承诺、权限和所需执行绑定，再连续接上截点后的增量。无需等待所有节点全部历史；各产地分别记录进度。追上只是必要条件，仍需获得负责人授予及确认执行能力。

成员变更由指定的身份/权限权威串行应用，以该权威的持久应用及必要执行边界生效为准，不要求所有离线设备回来确认。离线节点恢复后先更新权限版本，再处理指令。撤销设备不能只改界面列表；所有接受其指令的边界都要拒绝失效授权。无法取得所需权限新鲜度时拒绝敏感操作，而不是继续相信旧成员表。

如果权限权威尚未选定，就把它列为 R4 的未决设计条件，不能用“一次改一个”替代具体的一致性方案。

## 6. DS-Bot-App 借鉴的适用范围

| 条目 | 修正后的要求 |
| --- | --- |
| 地址筛选 | 标注 LAN、私网、公开入口等可达范围，并验证身份及连接健康。内网地址可供同一局域网客户端使用；不能当作任意外网都可达，也不能一律删除。链路本地地址需要匹配接口/网络作用域 |
| 手动线路优先 | 自动发现不得覆盖手动配置；手动线路不可达时，可按已授权策略切到已验证的其他线路，并保留原配置及失败状态 |
| 配对身份 | 主机身份与线路证书要区分；证书续期、隧道入口变动不自动等于主机换身份。所有线路验证同一主机身份，但具体验证方式须符合传输结构 |
| 旧通知 | 不重复弹旧通知；仍待处理的审批、失败和待办继续出现在状态/通知中心。已读不等于已处理 |
| 后台轮询 | 可采用有界退避，但不能保证系统始终允许运行；后台通知延迟不能冒充前台同步或首回应时延通过 |
| 操作后重读 | 使受影响资源的旧快照失效，重新读取后再做依赖它的操作；不要求所有无关缓存作废。重读失败时状态为未知，不自动重复动作 |
| 会话分段 | 保留稳定对话、任务及承诺身份；摘要标明覆盖范围并可追溯到原文。旧段任务结果引用原任务，投递到当前段而不复制任务 |
| 安装与回滚 | 固定版本、校验来源、离线包和失败回滚可以保留；按预装方案实施，不混进 Runtime 投影改造 |
