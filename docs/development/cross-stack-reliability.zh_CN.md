# App、Runtime 与固件强制开发准则

## 适用范围与权威入口

所有修改 Pocket Hub（`companion/`）、小幽 Runtime（`runtime/`）或固件
（`main/`、`components/` 及固件配置／工具）的 Agent，必须在修改前阅读本文。
影响这三个项目的提示词、模型、依赖、持久化、路由、权限及部署改动同样适用。
[根目录 AGENTS.md](../../AGENTS.zh_CN.md) 仍是指令入口；目录内的 `AGENTS.md`
只负责指向本文和相应项目指南。

每次修改都必须满足以下三项要求，包括标为 UI、清理、优化或新增功能的修改：

1. 保留原本能够正常使用的用户流程。
2. 从用户发送动作开始，**3,000 ms 内**在界面显示有实际意义的助手正文，覆盖
   所有受支持的输入方式和已连通的客户端链路。
3. 同一共享会话和任务在所有参与客户端上保持一致，包含中断及恢复之后。

这些是验收要求，**不代表当前实现已经满足**。已有缺陷必须记录为基线失败并
排查，不能据此降低门槛。只有主人明确指示才能改变产品范围或这些要求。缺少
设备或测试依赖应标为 NOT RUN，不能标为 PASS。

## 保住可用基线

改变行为之前：

- 按根目录 `AGENTS.md` 读取保留的共享历史，再用当前代码、运行版本和可复现
  结果核对。记录已有修改，保留其他 Agent 的工作，协调共享文件的编辑。
- 明确受影响的用户流程及相邻依赖。记录 App 版本、Runtime 修订、固件身份、
  传输路径和配置变体，不包含秘密。区分源码修改与实际安装版本。
- 修改前运行最小相关现有检查。修复 bug 时先复现，再在对应状态、协议或生命
  周期边界补回归检查。只能在真机复现的问题，除可做的主机测试外，还必须有
  可重复的真机验收步骤。
- 写清必须保留的行为、预期变化、与已安装各端的兼容性、验收检查，以及安全
  回退／恢复路径。

修改后用同一基线重跑受影响和相邻流程。禁止通过删功能、削弱断言、延长时限、
隐藏错误、清空历史／设置，或拆掉记忆、审批、安全机制和任务编排，让新链路
看起来更快或测试变绿。修改应落在最小责任层，避免无关重写。分别记录原有失败
和新增失败。

线协议、HTTP/SSE 事件、BLE 消息、ID、状态值与持久化数据都是兼容性契约。
优先使用增量扩展、能力／版本协商、未知字段安全处理及显式迁移。测试新 App
与已安装 Runtime／固件，以及受支持旧 App 与新 Runtime 或固件的组合。不得
隐含要求三端同时升级。升级和回退后必须保留配对、权限、消息历史、待处理请求、
审批归属及更新／恢复能力。

## 3 秒首回复契约

### 测量定义

`TTFT = 首段有实际意义的助手正文显示时刻 - 用户发送动作时刻`。
在发起端使用单调时钟计算耗时。文字从用户点击发送开始；手机或设备语音从
松开录音按键或接受语音结束事件开始。语音上传、BLE 传输、转录、建连、重试、
排队、锁等待、上下文准备、模型启动、解析、转发和 UI 调度全部计入。还要验证
其他活跃参与界面第一次显示正文的时间；只有 API 耗时不够。不能把起点挪到
服务端接收或转录结束，也不能因重连、重试、降级而重新计时。

只有与本轮问题有实际关系的非空助手正文才算首 token。输入动画、传输心跳、
只有推理的事件、HTTP 接收确认、固定占位应答、任务卡和错误提示都不算。
耗时的工具／助手任务必须允许模型先给出真实的初始回复，再异步继续；首段
文字和建卡均不代表用户要求的工作已经完成。有意义的回复依赖慢工具时，同样
受此时限约束，不得编造结果。

要求是**每个成功样本都 <= 3,000 ms**，不是平均值或某个百分位目标。冷启动、
长历史、并行任务、后台恢复、切换来源、重试、直连／远程路径和受支持的降级
路径都要覆盖。不得悄悄从报告中排除慢样本和超时。

### 实现约束

- 客户端、Runtime、上游模型和固件诊断串联同一个请求／轮次 ID。记录分阶段
  耗时（采音／ASR、建连／上传、排队／上下文、上游首段正文、流转发、首次
  显示）及版本组合。不能直接相减不同机器的墙上时钟，也不能为测速记录私人
  消息、音频内容或凭证。
- 向关键路径加工作前，先分配好各阶段的 3,000 ms 总预算。有意义的增量正文
  到达后立即转发，不能等整句或完整答案。限制不断增长的历史／上下文与耗时
  发现流程，但不能悄悄丢掉必需记忆或权限检查。
- 工具、转录、下载、更新或模型运行期间，对话、消息订阅／同步、取消、审批
  与健康检查必须保持响应。一个繁忙工作线程或共享锁不能串行阻塞无关流程。
  必须测排队与过载，包括同一会话的顺序等待。
- 首段正文、空闲和总时限必须有独立计时／取消路径，即使没有任何事件或上游
  一直只有心跳注释也会触发。HTTP 已连接或心跳正常不代表模型能够回复。
- 重试与已获授权的降级共用原始截止时间。禁止每次尝试重置计时、重复提交
  一轮、静默切换数据目的地／模型，或为达标移除必需行为。取消被替代的工作，
  限制资源占用；明确已接收但变慢的一轮继续还是停止，并让各端对齐最终状态。

### 依赖不可用时

断网、Runtime 未开机或上游模型卡住时，无法保证三秒内产生真实模型正文。
必须在 **3,000 ms 内**明确显示不可用、排队或延迟状态，提供恢复／取消操作，
保留请求，不得显示为已经回答。不能确认是否接收时应如实显示，核对后再重发。
这类样本**未达到首回复要求**；及时失败反馈属于独立恢复检查，不能算 TTFT
通过。在必需链路完成实测、依赖／降级能够支撑之前，不得声称无条件保证。
记录剩余缺口并继续范围内的修复，不能隐瞒。

## 连接与恢复契约

- 显式区分未连接、连接中、认证／就绪、重连中、状态过期和失败。必要时显示
  实际选中的 Runtime／设备和缓存时间。健康检查、授权、消息订阅就绪和模型
  就绪是不同事实；一项成功不能抹掉另一项失败。
- 使用有上限的超时与退避。覆盖切网、休眠／唤醒、后台恢复、App／Runtime
  重启、BLE 重连与流中断。重新认证并订阅后补齐遗漏状态，不能要求用户靠
  清空数据或重新配对来恢复普通传输失败。
- 传输重试保持同一逻辑轮次 ID 和负载。只有具备覆盖相关失败／重启时间窗口
  的明确幂等契约，才能重试写入。确认丢失或流中断后应查询／恢复已接收轮次，
  不能再提交一份。
- 回调、待处理请求、审批、游标和凭证必须绑定原 Runtime、会话、设备和连接
  代次。旧连接迟到事件不能修改新选中的来源，也不能批到别的任务。权限拒绝、
  无效输入和认证失败不能变成无限网络重试。
- 取消／关闭过时的请求、订阅器、定时器、音频会话及设备工作任务。Android UI
  和固件按键／LVGL 回调不得阻塞；继续遵守根指南中的 LVGL 加锁、内存和
  销毁规则。

## 多端消息一致性契约

对于**同一个已获授权的共享会话**，App、Runtime 和设备必须在消息身份、顺序、
各视图声明窗口内的内容、任务目标及状态上保持一致。参与该共享会话的桌面
会话同样适用；不能按文字相同就合并无关／私人的桌面对话。Runtime 负责共享
会话的持久化权威记录；导入或观测的桌面会话保留明确来源及受支持的读写边界。

- 携带稳定的来源／会话、轮次和消息身份，以及单调事件序号／修订号。不同
  轮次出现相同文字仍是两条消息。按身份去重，不能仅按内容或时间戳去重。
- 确认已持久接收前，先保存用户消息、待处理工作意图和重试身份。确认或广播
  完成前，先保存最终回复／终态。区分本地待发、Runtime 已接收、流式回复中、
  完成、失败和取消。崩溃／重启不能悄悄丢掉已接收工作或重复执行。
- 将本地预显示消息、流增量、消息订阅更新及历史快照合并到同一逻辑消息。
  忽略重复／更旧修订；旧 partial 或快照不能覆盖更新的 final／取消状态。
  明确终态转换和多端并发发送时的确定顺序。
  保留线协议中增量与快照的不同语义：当前 HTTP `partial` 事件替换完整临时
  正文，更新的空快照也应撤回之前的临时正文。不能追加快照或丢弃有效撤回。
- 针对缺口、保留窗口过期、序号重置和 Runtime 重启，提供游标重放及快照／
  对账路径。衔接快照与实时订阅时不能出现漏消息窗口。应用状态与游标一并
  持久化，成功应用后才推进游标。不能把缺口悄悄当成已经同步。
- 在线活跃客户端必须在已提交消息／状态增量后的 **3,000 ms 内**反映变化；
  这不能替代从发送到首次显示的时限。认证重连后，从传输就绪起 **3,000 ms
  内**对齐当前会话／最新状态，旧历史的进一步回补应明确显示。离线客户端
  保留待发状态，恢复后收敛；不能宣称断线期间已经即时远程送达。
- 慢客户端、翻页、历史裁剪和任务删除不得抹掉保留的聊天记录或阻塞其他端。
  保留会话／任务／pin 归属、后台完成消息、审批和终态。主动删除应是有范围、
  有明确契约的显式操作。
- 固件可以展示有上限的最近窗口／节选，无需保存完整档案；截断、缓存和离线
  状态必须如实标明。窗口内消息必须与权威记录一致。内存限制不能成为编造
  成功、丢掉已接收请求或恢复旧终态文字的理由。

## 必须执行的回归与故障矩阵

行为修改前后都要运行受影响行及相邻流程。修改聊天、传输、同步、生命周期、
模型／提示词或协议时，运行**全部适用行**。只有给出具体范围理由才能标为不
适用；设备不可用应标 NOT RUN。顺序、去重、计时器和故障注入采用确定性的
主机／集成测试，真实显示耗时和传输恢复另用真实 App／Runtime／设备验收。

| 场景 | 必须提供的证据 |
| --- | --- |
| 文字、手机语音、设备语音 | 目标正确且仅一份回复；耗时包括 ASR／转发；重复录音／松开／取消可用 |
| 热启动、冷启动及长历史 | 首段可见正文 <= 3,000 ms；不丢记忆、权限或历史 |
| 慢工具、繁忙工作线程及同时发送 | 对话仍可响应；同会话顺序确定；不重复产生副作用；审批／取消／订阅可用 |
| 正常流、空流、仅心跳、上游卡住 | 首段正文／空闲／总时限正确；不得伪造 TTFT 达标；各端进入真实状态 |
| 发送前断网、接收确认丢失、流中断 | 区分待发／已接收；恢复同一请求，不重复消息或工作 |
| 直连／远程、切网、BLE 重连 | 来源／连接状态明确；重试有界；补齐遗漏消息 |
| 后台／前台、切换来源及 App／Runtime／设备重启 | 恢复持久历史／待处理状态；迟到回调不污染另一来源 |
| 两个在线端及一个离线后回来的端 | 增量／最终状态收敛、顺序稳定、每条消息一个气泡；记录传播／恢复时间 |
| 重复／乱序事件、快照与流竞态、空 partial 撤回、游标重置 | 新修订生效；替换／增量语义正确；不漏轮次、不合并重复文字、不从 final 退回 partial |
| 翻页／裁剪、设备窗口限制及长回复 | 保留聊天不丢失；节选真实；当前窗口与终态一致 |
| 审批、助手追问、后台完成及取消 | 原任务／Runtime 归属正确，编排保留；各端状态一致 |
| 受支持混合版本、升级／回退及更新中断 | 契约兼容；保留数据／配对；更新／恢复能力可用 |

对每条受影响的成功输入／传输路径，至少采集 20 次热状态发送，并对每个适用
状态转换／故障场景重复三次。记录尝试次数、成功数、未达标／超时数、p50、
p95、最大 TTFT，以及传播／恢复时间。所有成功 TTFT 样本必须满足 3,000 ms，
不能仅凭百分位通过。候选版本实际安装后再重跑冒烟验收，不能只测模拟上游或
源码工作区。

## 验证与交付

使用项目已有命令，不另造替代流水线：

```bash
# 仓库根目录；完整门禁需要激活 ESP-IDF 5.5.3。
./tools/validate.sh --static
./tools/validate.sh

# Runtime 修改：在 runtime/ 下运行。
python3 -m unittest discover -s tests

# Android 修改：在 companion/android/ 下使用 JDK 17 和 Android SDK。
gradle testDebugUnitTest assembleDebug
```

仓库检查、主机测试、构建和模拟流测试不能证明真实端到端延时或设备收敛。
实现可靠性修改时，应在责任层补齐缺少的可执行覆盖；不得把本文或现有静态门禁
描述为已经实现的在线 SLA 监控。纯文档修改报告文档／静态检查，并说明未执行
运行时验收；无需因此发布 App 或烧录。

继续遵循现有[App 交付流程](../../companion/README.zh_CN.md#发布一次-app-改动开发者和-ai-agent)、
[Runtime 重启规则](../../runtime/README.zh_CN.md)和
[固件真机交接](ai-guide.zh_CN.md#主动询问真机测试)。
构建／发布、安装版本核对和真机验收是三个独立事件。中断活跃 Runtime 或烧录
仍须按这些规则取得授权。保留已知兼容的恢复产物及迁移路径；回退必须考虑
持久化格式变化。

每次行为修改的交付必须包含：

```text
Versions/configuration: App / Runtime / 固件 / 传输路径（不含秘密）
Regression: PASS / FAIL / NOT RUN；基线、受影响及相邻流程
First response <= 3s: PASS / FAIL / NOT RUN；样本、p50/p95/max、未达标数
Connection recovery: PASS / FAIL / NOT RUN；故障路径及恢复时间
Multi-end sync: PASS / FAIL / NOT RUN；客户端集合、范围、收敛证据
Build: PASS / FAIL / NOT RUN
Host tests: PASS / FAIL / NOT RUN
Device tests: PASS / FAIL / NOT RUN
Unverified: 缺少的场景、安装版本验收、依赖缺口
Recovery: 兼容的回退产物／数据路径及所需授权
```

必需检查失败时，不能声称全部验收通过；缺少证据的必需项应保留 NOT RUN 和
待验证状态。保留并交付可审阅的工作及其缺口，但不能悄悄把已知回归发布／部署
为可用版本。告诉主人具体影响及恢复／修复步骤。Agent 能自行执行的常规检查，
不得再让主人重复操作。
