## 1. 收敛后的总问题

**系统内部的结构直接暴露给了上层代码和用户：同一件事有多条路、多个名字、多个归属。**

三个根因，下面每条问题都归到其中至少一个：

| 根因 | 含义 | 表现 |
| --- | --- | --- |
| R1 多条路 | 同一件事有两三条实现或入口，各自带兜底 | 回复双通道、feed/sync 并存、7 个发送入口、5 种“记录”视图、多处审批入口 |
| R2 多个名字 | 同一个东西在代码和界面里叫法不同 | 电脑有 5 种身份键；“连不上”有 6～7 种说法；“对话”有近 10 个名词 |
| R3 归属不清 | 状态该谁说了算没定，只好两边都存、都兼容 | 置顶/归档/已读存在手机按地址区分；手机反向上传历史；旧版 Runtime 兼容分支一直保留 |
| R4 没有呈现层 | 原始数据、调试工具和说明文字直接上屏，没有经过“给用户看”的整理 | 工具调用编号、IP、固件哈希、蓝牙重连日志上屏；用长段说明代替清楚的设计；按钮没有主次 |

收敛方向用一句话说：**一条下行通道（sync）、一个发送入口、一种电脑身份、两类东西（聊天 / 在做的事）、每屏一个主动作，状态以 Runtime 为准。**

## 8. 主 agent（小幽）的状态

### 8.1 现状盘点

小幽“知道什么、正在做什么”散在多处，没有一个统一的状态模型：

| 层 | 存放 | 取值 / 内容 |
| --- | --- | --- |
| 卡（任务） | `state/cards.json`、`cards.py` | `talking / working / waiting / done / failed / cancelled / unknown`，另有 `monitoring_only`、`mesh_origin`、`queued`、`approval`、`run_id` 等标记；其他模块还用到 `unavailable`、`turn_ended`、`relay_queued`、`closed`、`superseded`、`expired` 等 |
| 消息 | 统一消息日志 `cards.log.jsonl`、`messages.json` | `queued / running / generating / done / failed / incomplete / interrupted`… |
| 她能看到的对话 | `transcript.json` | 每个对话最近 6 轮（`BACKGROUND_TURNS`），补课时 8 轮（`SEED_TURNS`） |
| 她能看到的事 | 每轮提示词里的卡列表 | 进行中的卡 + 最近 5 张已结束的卡（`RECENT_FINISHED_CARDS`） |
| 正在说话 | 内存里的 `_speaking` | 每个对话一个打断事件，不落盘 |
| 记忆 / 承诺 | `memory/owner.md`、`promises.json` | 现在只有 3 条记忆 |
| 帮手会话 | `sessions.json`、`workspace` | 每个帮手接续用的会话 |

同一件事至少有三份记录：卡状态、消息日志、她的 `transcript`。三份之间没有强制同步。

### 8.2 问题

### 8.3 收敛方向

- **分开三种东西：** 对话轮次（主人说、她答）、任务（交给帮手的事）、提醒或承诺。闲聊只是轮次，不开卡；只有派出去的事才是任务。
- **任务只有一套状态：** 排队 → 进行中 → 等你确认 → 完成 / 失败 / 已取消。其他标记（同步来的、别的电脑的）作为属性，不作为状态。
- **任何终态都要回到原对话：** 完成、失败、取消都在 `transcript` 和主对话里留一句她的话，并更新相关承诺。
- **取消要记录发起方：** 写明是 App、电脑端、她自己还是网状网络里的另一台，以及原因。
- **显式的当前焦点：** 对话里记住“正在谈的那件事”，用来解析“这个”，不再每轮从最近 5 张卡里猜。
- **同一请求去重：** 已改为按请求编号去重，文字相同、编号不同就是新消息；避免重发靠界面始终显示真实状态（完整方案第 8 节）。

## 10. 目标与可量化指标

## 11. 建议顺序

> 整体执行以[完整方案](xiaoyou-agent-model.zh_CN.md)第 6 节的实施顺序为准；下面是只看本清单时的顺序。

1. 低风险清理：删 feed 与旧版兼容（C3、S4 部分）、统一发送入口与后台请求包装（C4～C7）、统一身份键（C8）。
2. 状态归属：置顶/归档/已读改由 Runtime 保存（S1～S3），随后删除“同步本机整理”。
3. 回复只走 sync（C1、C2、C9）：收益最大，触及首响 3 秒与多端一致，必须按可靠性规则做回归。
4. 交互与文案：在 3 完成后做 U4（发送不挡）、I1～I7、U1～U6、V1～V12、M6；先出草图，主人确认后再改代码。其中 V4（无标题）、V9（帮手合并）、V11（调试信息挪走）不依赖第 3 步，可以提前做。M1～M5、A1～A7 在 Runtime 侧，和第 3 步一起做；A1（取消要回到对话）和 A4（记录发起方）改动小，可以先做：回复只走一条路后，M3、M4 更容易根治。
